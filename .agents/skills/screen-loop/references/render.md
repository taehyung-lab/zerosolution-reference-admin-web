# 화면 결과일 때 — 근거와 관찰

결과를 판정하려면 렌더·포커스·키보드·문구·navigation·부모 화면 상태를 봐야 하는 요청에서 읽는다.
7단계·계약 skill·완료 rubric은 [SKILL.md](../SKILL.md)가 소유하며 여기서 반복하지 않는다.

## 근거를 읽는 순서

**바뀌는 것만 연다.** 제품 값(문구·옵션·권한·기본값·컬럼 집합)이 바뀌면 아래 1~4가 근거다.
구조·상태·접근성만 바뀌고 제품 값은 그대로면 원장·디자인을 열지 않고 5와 계약 skill의 해당 절로
닫는다. 어느 쪽인지 모르면 1만 먼저 보고 정한다.

1. 원장의 해당 화면과 연결 전이. 확정 답이 적용되면 판정 정본, 기대·실측 전이가 필요하면 시나리오 절을 읽는다.
2. 구성의 미열거·충돌·시각 대조가 있으면 inventory README의 원문 접근 절차로 실제 원문을 판독한다.
3. 부모·목적지 route와 실제 소비자를 확인한다. 필요한 연결 범위는 [screen-loop](../SKILL.md#요청의-종류)가 정한다.
제품 값은 원장·그 값의 원문, 파일·URL 조립은 계약 skill, 실행 사실은 소비자·테스트가 소유한다.
다른 도메인이나 형제 화면의 값은 제품 근거가 아니다. 연결 목적지는 자기 원문을 읽는다.
색인·원장·시나리오의 존재나 부재를 완료 또는 구현 금지로 판정하지 않는다.

## 관찰표 — 3단계에서 채운다

| 축 | 무엇을 적나 |
| --- | --- |
| **구성** | 이 화면에 실제로 있는 surface 목록. 없는 책임을 빈 파일로 만들지 않는다 |
| **상태** | 서버 데이터 / URL / 폼 / 로컬 각각의 소유자. 같은 값이 두 곳에 있으면 설계 결함 |
| **상호작용** | 각 액션의 진입 조건, 성공, 실패, 되돌리기 |
| **연결** | navigation, 권한 분기, i18n 키, 부모·형제 surface와의 경계 |

미확인 행은 원문 접근 실패·제품 부재·기술 의존으로 구별한다. 접근 경로를 먼저 수행하고, 제품이 답하지 않는 부분만 해소 조건을 남겨 보류한다.

## 실측 방법

**결과가 `render`면 요청 크기와 무관하게 브라우저로 실측한다.** 화면이든 버튼 하나든 같다 — 가르는 것은
요청 문장의 크기가 아니라 결과가 렌더로만 판정되는가다. 직접 render한 unit test·typecheck·lint·build는
그 실측을 대신하지 않는다.

진입은 이미 떠 있는 로컬 앱의 실제 route나 host에 **그 저장소가 선언한 브라우저 수단**으로 한다. 이
저장소에서는 `aside-browser`로 `http://localhost:5174`에 들어간다 — 인증 API의 CORS 허용 목록에 있는
origin이고 `5173`은 이관 대상 저장소가 쓴다. 포트를 바꿀 때는 그 저장소의 dev 서버가 실제로 그 포트를
서비스하는지 먼저 확인한다. 실 세션·실 토큰으로 보는 것이 실측이며, 이관 대상에서는 그 제품이 선언한
수단과 origin으로 바꾼다. 실행 명령은 README와 `package.json`이 소유한다.

`tests/e2e/`의 Playwright는 실측 수단이 아니라 **회귀 그물**이다. 가짜 토큰과 mock으로 돌아 로그인·실
서버를 타지 않으므로 수용을 증명하지 못한다([도달 상태](../SKILL.md#도달-상태)). 실측한 것 중 되돌아올
전이 하나를 그 화면·전이를 만든 같은 작업에서 spec으로 남기고, 단언은 전이·URL·상태 보존 같은 제품
동작으로 한정한다 — fixture의 id·값에 걸면 이관에서 죽는다. 앵커가 없는 기존 화면을 소급해 채우지 않는다.

제품 원문 관찰 방법은 `product.json`이 연결한 inventory README가 소유한다. 아래는 **진입한 뒤 무엇을
관찰하는지**다.

- 어떤 화면을 어떤 상태로 열었고, 무엇을 눌렀고, 무엇이 일어났는지를 적는다.
- 목록은 필터·정렬·페이지 전이가 URL에 남고 새로고침으로 복원되는지 본다.
- 폼은 검증 실패, 저장 성공, 저장 실패, 미저장 이탈을 각각 확인한다.
- 실 서버가 연결되지 않은 저장소의 상한은 [도달 상태](../SKILL.md#도달-상태)의 **시나리오 구현 완료**다.
  그 너머는 `미확인`이며 실 서버가 있는 제품에서만 판정한다.
- CSS 픽셀 대조를 기본 요구로 삼지 않는다. 제품 구성·정책은 인벤토리와 대조하고, 시각 구조·스타일이
  성공 조건이면 실제 디자인 원문과도 비교한다.
