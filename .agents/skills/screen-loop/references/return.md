# 복귀 — 무엇이 어긋났을 때 어디로

[SKILL.md](../SKILL.md) 의 7단계가 막혔을 때만 읽는다. 각 행은 실제로 겪은 어긋남이며, 겪지 않은 경우를 미리 채우지 않는다.

## 어느 단계로 돌아가는가

| 무엇이 일어나면 | 어디로 |
| --- | --- |
| 요청한 화면이 원장 색인에 없다 | **2.** 원장 파일에서 절을 직접 찾는다. 없으면 `미확인`이지 부재가 아니다 |
| 색인 id 가 `group` 이라 화면 하나를 가리키지 않는다 | **2.** 원장 표 본문에서 화면을 직접 분해한다 |
| 표 셀·산문·판정 문서가 다른 시점을 말한다 | **2.** `product.json` 이 연결한 inventory README 의 판독·근거 수명 규칙으로 실제 원문을 다시 확인한다. 확인한 출처·시점·방법으로 정본을 갱신하되, 자기 구현 설명으로 관찰·정책·미확인을 바꾸지 않는다 |
| 이름이 소유를 오도한다 | **2.** route 단위로 걸어 실제 소유자를 찾는다 |
| 선택한 계약 절이 바뀌는 경계를 소유하지 않는다 | **2.** `description` 으로 소유자를 다시 고른다 |
| 같은 값을 Query·URL·Form·로컬에 복제했다 | **3** |
| 단순 조립을 계층·wrapper 로 감쌌다 | **3** |
| 형태가 계약과 다른데 이유가 없다 | **5** |
| 공용 계약을 한 소비자를 위해 넓혀야만 요청이 만족된다 | **구현 이탈.** [승격 심사](../../shared-ui-contract/references/promotion.md#admission-test)에 답하지 못하면 feature-local |
| 원문에만 있는 요구를 발견했다 | **1.** 구현 요구와 영향 범위에 추가하고 inventory README 의 근거 수명 규칙으로 원문 근거를 기존 정본에 수용한다. 코드에서 역으로 원장 행을 만들지 않는다 |

## 어느 문서가 고쳐야 하는가

| 차이 | 소유자 |
| --- | --- |
| 원장 행 없음·낡음·원문 행 누락 | `product.json` 이 연결한 inventory 의 근거 수명 규칙 + 해당 문서와 표 형식. 실제 원문에 없으면 제품 사실 부재로 처리 |
| 표 ↔ 산문 ↔ 판정 문서 충돌 | 실제 원문·사용자 결정을 따라 판정 문서 + 원장 셀을 고치고, 답이 없으면 사용자 질문. 코드는 어느 쪽의 근거도 아니다 |
| 제품 사실 부재 | 사용자 질문. 그 경로는 답 전까지 구현하지 않는다 |
| 계약 문장이 없거나 모호 | 해당 계약 skill 의 reference. 도메인 이름 소비자 표는 만들지 않는다 |
| 공용 semantics 드리프트 | [ADR 0014](../../../../docs/decisions/0014-single-screen-shape.md) + shared-ui-contract |

소유자가 없는 차이는 새 정본을 만들지 말고 보고에 남긴다.
