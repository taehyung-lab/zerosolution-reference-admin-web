# Access and session incidents

Read this file only for access/session incident presentation or deciding which UI surface renders a normalized error.

- Error location is caller-decided from operation context and normalized kind; shared UI renders caller-owned content but does not classify API errors.
- The four placement outcomes are decided in `src/api/error-outcome.ts`: `resolveErrorOutcome(context, kind)` → `'none' | 'feature' | 'incident' | 'root'`: `route-not-found`/`render`/`route-loader`/`fatal` contexts → root, except a `route-loader` `unauthorized`/`forbidden` → incident (2026-09-11); `prefetch` + `forbidden` → none; `pre-auth` → feature for everything except `cancelled`, because a sign-in or 2FA failure ends no session and belongs on the screen that asked for the credential; otherwise `cancelled` → none, `unauthorized`/`forbidden` → incident, every other kind → feature, and `isFeatureError(error)` is the `unknown → ApiError` guard a feature uses before showing an error inline. App and feature surfaces consume that decision instead of repeating error-kind groups.
- `IncidentBoundary` owns terminal auth/access presentation, and it is the only surface for `forbidden`. It renders `AccessDeniedPage` (`src/app/error-boundary/StatusPage.tsx`) as a Radix modal cover; focus moves to that action and the screen underneath stays mounted, inert and aria-hidden. The boundary fails closed: it shows the cover only for an incident marked `origin: 'route-loader'` (a navigation's required query, republished by `loadRequired`) for a refused query that a mounted screen observes (matched on `state.error` or `state.fetchFailureReason`), or for any refused mutation (a user action started it); a preload on link hover or an unobserved query stays silent — except a preload that refetches a key a mounted screen already observes (detail → edit hover after `staleTime`): that 403 is observed and covers, which is accepted. Acknowledging goes back, or home when there is no history. The router error components render nothing for `forbidden`, so the cover never doubles with a page.
- A remaining-time/extension/expiry-warning boundary is **not implemented**; the current app lifecycle is `AuthProvider` sign-out only. The target product owns whether it needs one, its timing and wording through its inventory/scenario. Do not infer a timer policy from this reference. If required, the app lifecycle owns it without copying Query session data.
- Observerless prefetch has no loading or incident surface.
- `ErrorTrace({ value: { requestId?, status?, kind? } })` directly reads its five labels from the `shared` namespace and renders nothing when all three are absent. List, detail, and root callers pass only `ErrorTraceValue` (an `ApiError` satisfies it structurally); they do not repeat the disclosure labels or pass raw messages.

Classification or reissue changes also require the API auth/transport reference. Test safe copy, live-region behavior, focus, recovery action, and the incident state actually changed.
