# 0013. 구현 요청 워크플로우와 문서 체계

- 상태: 대체됨 — 현재 라우팅 결정은 ADR 0015·0016
- 날짜: 2026-09-14
- 적용 범위: 루트 실행 기준, `screen-loop`, 기록 프로토콜, 문서·검사의 소유권 배치
- 출처: Claude·Codex 3라운드 적대적 리뷰. 이 ADR이 `docs/design/2026-09-14-*.md` 3건과
  `docs/research/2026-09-14-*.md` 1건을 대체한다

이 ADR은 **왜 이 형태를 골랐고 무엇이 반증이면 되돌리는가**만 소유한다. 실행 절차는
screen-loop, 전역 경계는 [AGENTS.md](../../AGENTS.md),
검사 소유는 [검사 안내](../../scripts/contracts/README.md)가 소유한다.

현재의 단일 진입·라우팅 구조는 ADR 0015·0016이 대체한다. 아래 단일-entry workflow는 역사적 결정이며,
버린 대안·알려진 손실·당시 관찰은 같은 실패를 다시 제안하지 않도록 여전히 유효한 기록으로 남긴다.

## 결정

1. **루트는 안내 데스크다.** 라우팅·전역 함정·완료·규칙 변경 게이트만 갖는다. 162줄에서 50줄로
   줄였다. 경로→skill 표, 레이어 그림, 제품 사실 상세, 절 번호 체계를 뺐다.
2. **구현 요청은 `screen-loop` 하나로 진입한다.** 7단계와 완료 rubric을 그 skill이 소유하고,
   2단계에서만 화면/비화면이 갈려 `render.md` 또는 `nonrender.md`를 고른다. 제품 값이 바뀌는지의 분기도
   같은 2단계 안에 두고 단계를 늘리지 않는다.
3. **게이트는 존재가 아니라 결과를 본다.** `prepare`/`checkpoint.json`/`review.json`/
   `independentReview` 필드/드릴 산출물 3종/`.ai-work` 강제 경로와 세 런타임 hook 설정을 제거했다.
4. **읽기는 필요한 절만.** `SKILL.md` 전문 읽기 강제와 원장 4종 관례적 전량 탐색을 뺐다.
5. **read-only 증거 선택기는 남는다.** `scripts/agents`의 기록 부분을 버리고 `scripts/evidence`로
   분리했다. `contracts:check`가 실제로 전이 의존하기 때문이다.
6. **`screen-shape.mjs`는 분할했다.** 이름→segment 배치 휴리스틱은 폐기하고 source 검사만 남겼다.
7. **surface 색인은 선택 도구이지 게이트가 아니다.** 색인에 없는 화면은 원장 소유자에서 직접 찾고, 거기에도
   없을 때만 미확인이다. 색인의 존재를 구현 정지 조건으로 삼지 않는다.
8. **제품 근거와 공용 계약을 분리한다.** 공용 skill은 도메인 중립 규칙만 갖고, 도메인 사실은 `product.json`이
   연결한 reference와 실제 consumer 코드·테스트가 소유한다. 공용 계약의 소유 기준(첫 consumer가 아니라 반복
   검증된 의미)은 [ADR 0014](0014-single-screen-shape.md)가 소유하며 여기서 복제하지 않는다.
9. **요청은 확인된 환경·저장소 목적·요구 안에서 판단한다.** 결과에 영향을 주는 근거가 없는 외부 환경의 예외만으로
   요청을 기각·변형하지 않되, 현재 환경 안의 더 나은 설계는 근거와 영향과 함께 제시한다. 레퍼런스 저장소는
   일반화와 타 환경 평가의 유혹이 가장 큰 곳이라 이 문장을 루트에 둔다.
10. **공용 계약이 없는 control은 host surface의 workflow가 소유한다.** 라우팅 문장이 control 명사
    (select·dialog·table 등 전용 reference가 있는 것)와 workflow 명사(list·detail·form·bulk)로만 키잉돼
    있어, 버튼처럼 둘 다 아닌 control은 소유자에 닿지 못했다. 종류 표의 `컴포넌트 이름→component` 기본값이
    그런 요청을 `shared-ui-contract`로 밀어 오라우팅을 만든다. 새 reference를 만들지 않고 `screen-loop`의
    갈림 절에 소유 규칙 한 문단을 둔다.

11. **문서 변경은 실측으로 채택한다.** 같은 요구를 같은 조건에서 다시 구현하게 하고 전후를 비교해,
    같은 질문이 사라졌는지·예외가 줄었는지·검사가 실제 잘못된 결과를 잡았는지·다른 도메인을 정답으로
    삼지 않고 흐름이 닫혔는지로 판정한다. 기존 검사 통과는 코드 회귀만 말하므로 채택 근거가 아니다.
    절차는 `screen-loop` 7단계가 소유하고, 여기서 복제하지 않는다.
12. **한 역할에 문서 하나(2026-09-16).** 결정 4의 "필요한 절만"을 문서 수로 이어서, 목록·상세·폼 계약을
    각각 한 파일로 합치고 공용 단위는 catalog 한 표로 모았다(7 + 22 → 3 + 1 + 셋). 근거는 같은 규칙이
    여러 파일에 흩어지면 화면 하나를 만들 때 읽을 파일을 고르는 비용이 규칙을 읽는 비용보다 커진다는
    것이다. 화면 하나는 역할 문서 하나, 버튼·로직 하나는 catalog 행 하나를 읽는다(종류별 표는 `screen-loop`).
    문서는 판단 규칙을 담고 데이터 계약은 코드가 담는다 — 도메인 이름·소비자 목록·개정 이력은 문서에서 뺐다.
    그 문서들이 정한 화면 형태와 공용 경계 자체는 [ADR 0014](0014-single-screen-shape.md)가 소유한다.

## 이유

**외부 근거.** Anthropic이 클로드 코드 시스템 프롬프트 80% 이상을 지웠는데 코딩 평가가 올랐고,
그 엔지니어가 정리한 규칙은 (1) 규칙 대신 판단 (2) 예시 대신 인터페이스 (3) 점진적 공개 —
루트는 창고가 아니라 안내 데스크, 뻔한 것 말고 함정 (4) 반복 금지 (5) 자동 메모리
(6) 마크다운보다 코드·테스트·루브릭.

**실측.** 전환 전 루트 161문장 중 **42개(26%)가 금지문**이었다. `screen-loop`는 형태 절을 읽기 전에
`SKILL.md` 전체 약 **33KB**를 먼저 읽게 했다(그 문서 자신의 기록).

**존재 게이트의 자기부정.** 저장소가 세 번 인정했다 — "게이트는 네 칸의 **존재**만 본다",
"기록의 **존재**를 볼 뿐 검토의 질은 보지 못한다"(2회), "보고서는 기록이고 **반영된 diff가
산출물**이다"(그러면서 파일 3개를 요구). 의미를 못 보는 검사를 통과하려고 파일을 만들게 하는
구조였다.

**이름 휴리스틱의 공백.** `screen-shape.mjs`는 "이름이 규칙과 다르면 검사 대상이 아니다"라고
스스로 선언했다. 규칙을 이미 지킨 화면만 검사하므로 보장이 0이다. 반면 같은 파일의 source
검사는 실제로 발화한 이력이 있다(`SORT_MAPPING_EXCEPTIONS`에 등록된 실제 예외).

**색인 게이트의 위험.** 2026-09-15 설계안 하나가 "surface가 색인에 없으면 정지"를 제안했다. 채택했다면
`context.json`의 존재가 구현 게이트가 되어 결정 3과 모순된다. 색인은 위치 도구이고, 부재의 근거는 원장 소유자다.

## 버린 대안과 이유

| 대안 | 기각 이유 |
| --- | --- |
| 규칙마다 `R-ID` + 실존 검사 | ID가 남은 채 의미만 약해져도 통과한다. 새 원장·parser·커밋 규약을 동시에 만든다 |
| skill 6개로 재명명·재분할 | 오라우팅 감소 실측 없이 README·검사기·상호 링크·테스트 참조를 전부 깬다 |
| 루트 경로 표 + 일치 검사 | `description`과 이중 소유. 표를 지우면 검사도 불필요하다 |
| 생성물 read 게이트 | 이 저장소에서 과다 read 사고가 관측된 적 없다 |
| `/doctor`로 스킬 정적 평가 | 실행해 확인했다. 설치·설정·usage·skill 디렉터리 목록만 읽고 skill 본문을 best practice에 대조하지 않는다 |
| 스킬 레지스트리·카탈로그·접근제어 | 15팀 조직 문제. skill 5개 저장소에는 대체 없는 순증가 |
| auto-evolving skill | 가드레일 없는 자동 수정 루프는 영향만 키운다. 이 체계에 닫힌 루프를 두지 않는다 |
| 7단계를 9노드 그래프로 재분할(2026-09-15) | 분류·근거·계약 분리는 2단계 안의 분기 한 줄로 얻는다. 재번호는 render/nonrender·ADR·검사기 문장에 번호 drift를 만들고, 그 drift는 이 저장소가 이미 검사기를 두어 막아야 했던 실패다 |

## 알려진 손실

- **recorded audit 능력이 실제로 사라진다.** `prepare` 세션의 scope·hash·receipt 검사가 없어진다.
  대체는 git diff와 커밋 본문이다.
- **의미 소실은 자동으로 증명되지 않는다.** 루트·skill·gate 변경에서 삭제된 판별 기준의
  복원/이동/폐기를 실제 diff에서 대조하는 것은 독립 검토의 책임으로 남는다. 이 저장소는 같은
  실패를 두 번 겪었다(`a9ffc45`의 규칙 4건, 2026-09-14의 판별 기준 17건).
- **`screen-loop`라는 이름이 비화면 진입에 어색하다.** rename의 이득 실측이 없어 경로 안정성을 택했다.

## 재검토 조건

- 모델 ID·버전이 바뀌면 screen/nonrender/API/mixed 동일 corpus로 라우팅 오판정률을 다시 잰다.
  품질이 떨어지면 `description`과 `render`/`nonrender` 경계를 먼저 의심한다.
- 기록 모드 제거가 실제 감사 요구에서 결함을 만들면 공통 기본값으로 되돌리지 말고 별도 도구로
  재평가한다.
- 이름 때문에 오라우팅이 반복 관측되면 그때 rename 비용을 다시 계산한다.
- 토큰은 동일 revision·모델·effort에서 provider usage(input·cached·output)와 성공 task당 비용을
  비교하기 전까지 **미측정**이다. 문자 수 감소를 절감으로 쓰지 않는다.
