# 0015. 두 질문 라우팅과 제품 사실의 단일 소유

- 상태: 채택 — 2026-09-21 변경 책임에서 진입하도록 라우팅 수정, 제품 사실 단일 소유 유지
- 날짜: 2026-09-17
- 관련: [0014](0014-single-screen-shape.md),
  [0016](0016-skill-routing.md)

## 결정

무엇을 읽을지는 요구·현재 흐름·성공 조건에서 확인한 변경 책임으로 정한다. 기존 동작의 내부 변경은
해당 코드·계약·테스트에서 시작하고, 제품 값·동작을 정할 때 제품 근거를 확인한다.

한 surface의 관찰·정책·미확인은 `product/facts/<id>.md` 한 파일이 소유하고, 색인은 fact의
frontmatter에서 생성한다. 새 화면의 역할이 불분명하면 fact의 진입·상호작용과 `role`을 참고한다.
실행 절차는 [AGENTS.md](../../AGENTS.md#라우팅)가 소유한다.

2026-09-21 사용자 요청으로 문서 진입부터 실패 학습까지 재정리했다. 모든 역할 선택에 fact를 거치라는
지시가 구조·상태만 바꿀 때 제품 근거를 열지 말라는 계약과 충돌했다. 제품 사실 단일 소유는 유지하고,
변경 책임을 먼저 확인하도록 바꿨다. 작은 변경도 연결된 동작을 놓치지 않는지는 실제 작업에서 관찰한다.

## 결정 당시의 관찰과 이유

이전에는 한 surface의 사실이 inventory·judgment·scenarios·index에 나뉘었다. 관찰 하나를 바꿀 때
세 파일을 고쳐야 했고 실제로 서로 어긋났다. 단일 fact로 바꾼 뒤 제품 사실 갱신 경로는 3개에서 1개가
됐다.

요청을 screen·slice·component·logic·structure 같은 크기로 분류했을 때 “버튼 하나”가 화면 계약을
건너뛰었다. 결과의 검증 방법으로 고르면 작은 변경도 렌더로만 판정되는 순간 같은 계약과 관찰을 거친다.

옛 계약 29개, 143블록을 새 구조와 대조했을 때 그대로 옮긴 문서는 손실이 없었고 사람이 다시 쓴
문서에서만 판단이 빠졌다. 그래서 문서를 옮길 때는 이름이나 요약이 아니라 판단 블록의 처분을 확인한다.

## 대가

- 한 fact가 커질 수 있으므로 surface 경계를 계속 관찰해야 한다.
- 색인은 읽기에는 싸지만 생성 단계가 필요하다.
- 내부 변경과 제품 판단의 경계를 잘못 고를 수 있으므로 실제 누락은 해당 진입 설명으로 돌려보낸다.

## 버린 대안

- 제품 사실 위치를 별도 포인터 파일로 선언: 고정 경로와 중복되고 어긋날 소유자만 늘어난다.
- 네 경로 원장을 유지하고 색인만 생성: 갱신 경로는 여전히 세 곳이다.
- fact 열거와 코드 enum을 무조건 대조: 당시에는 대조할 실제 짝이 없어 빈 게이트가 된다.
- 요청 크기별 라우팅 표 유지: 작은 요청이 필요한 계약을 건너뛴 실패를 반복한다.

## 재검토 조건

- 같은 요구에서 같은 질문·예외·잘못된 화면 복사가 반복된다.
- 변경 책임으로 읽어야 할 계약을 찾지 못하거나 불필요한 근거 탐색이 반복된다.
- 한 fact가 여러 독립 surface를 담아야만 사실을 표현할 수 있다.

재검토는 문구 선호가 아니라 실제 diff, focused test, 필요한 브라우저 관찰로 판단한다.
