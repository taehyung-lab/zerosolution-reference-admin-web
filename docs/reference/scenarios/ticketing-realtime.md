# 시나리오 카드 — 발권 실시간

이 카드는 발권 화면의 호출 직전 흐름과, 신규 프로젝트에서 실시간 축을 열 때 먼저 지킬 규칙을 소유한다.
비교 대상의 코드·파일 구조·훅·누적 방어 로직은 설계 입력이 아니다.

표기: `[관측]` 운영 화면·프레임·결함 이력에서 직접 확인한 사실, `[선언]` 이 저장소 문서의 현재 경계,
`[추론]` 관측으로부터 좁힌 설계, `[미확인]` 답에 따라 구현이 달라지는 질문.

## 1. 사용자 시나리오와 현재 끝점

1. 공연을 검색해 고르고 회차를 정하면 예매 목록이 보인다 `[관측]`.
2. 발권할 행을 고른다. 선택 순서는 사용자가 정한 순서를 보존한다 `[관측]`.
3. 프린터를 고른다. 각 프린터에는 대기·인쇄중·오류·연결끊김 상태가 보인다 `[관측]`.
4. 발권 미리보기에서 티켓 이미지와 `테스트 발권`을 확인한다 `[관측]`.
5. 미리보기가 준비된 경우에만 `발권 시작하기`를 누를 수 있다 `[관측]`.

이 저장소의 화면 이슈는 **5번 버튼을 누르기 직전**까지다 `[선언]`. 프레임 수신·진행·완료·취소·재시작은
신규 제품이 실시간 계약을 붙일 때 여는 별도 축이다.

## 2. 흐름에서 확인된 사실

- 프린터의 현재 상태는 실시간 프레임이 진실이고, 목록에서 받은 값은 현재 연결의 프레임 전까지 잠정값이다 `[관측]`.
- 발권 가능 여부는 지금 연결에서 받은 상태로만 판정한다. 이전 연결의 상태로 발권하지 않는다 `[추론]`.
- 발권 전 상태 확인을 기다리는 프린터는 발권 불가로 보인다. 시간 안에 답이 없으면 오류로 표시하고,
  늦은 답은 표시만 복구하며 발권을 자동 재개하지 않는다 `[관측]`.
- 미리보기 준비 전에는 시작할 수 없고, 취소는 서버가 준 작업 식별자가 있을 때만 가능하다 `[관측]`.
- 한 프린터는 한 번에 한 장만 인쇄한다 `[관측]`.

## 3. 관측된 실패

아래 13건은 사용자에게 실제로 드러난 실패다 `[관측]`.

| 실패 | 실패를 허용한 설계 |
| --- | --- |
| 연결 단절 경고가 인쇄 중인 행을 따라다님 | 행을 특정할 수 없는 사건을 행에 붙임 |
| 한 프린터에 `발권중` 행이 누적됨 | 행마다 독립으로 진행 증거를 해석함 |
| 다른 프린터·운영자의 프레임이 내 행을 바꿈 | SN·타이밍으로 귀속을 추정함 |
| 프린터 재시작 뒤 완료 상태가 사라짐 | 행의 결말을 세션 수명에 묶음 |
| 종료된 공연에 발권할 수 있었음 | 발권 가능 조건에 공연 기간이 없음 |
| 실시간 갱신이 checkbox 조작을 막음 | 갱신이 사용자 선택 상태를 다시 만듦 |
| alert가 선택 프린터 표시를 얼림 | alert와 선택 표시가 같은 상태를 공유함 |
| 늦은 실패가 성공한 미리보기를 덮음 | 요청 취소와 응답 채택이 분리됨 |
| 서버가 보내는 진행 카운트만 사라짐 | 신선도·연결 판정으로 표시까지 숨김 |
| 미수신이 가짜 `0/0`으로 보임 | 없는 숫자를 0으로 채움 |
| 완료 신호 유실 뒤 영원히 진행 중으로 남음 | 종결을 한 신호에만 의존함 |
| 단절 뒤 결과 미상 행이 `발권중`으로 남음 | 관측의 부재를 진행으로 해석함 |
| 선택 행 순서가 뒤집힘 | 선택 집합에서 순서를 잃음 |

## 4. 실시간 축을 열 때의 다섯 규칙

1. **한 프린터의 현재 상태는 서버가 보낸 최신 프레임 하나다.** 여러 출처를 합성하지 않으며,
   프레임 전 목록 값은 잠정 표시일 뿐이다 `[추론]`.
2. **행의 결말과 작업의 진행은 다른 축이다.** 한 셀에 함께 보일 수 있지만 서로 덮거나 서버 원래 값을
   파괴하지 않는다 `[추론]`.
3. **프레임 귀속은 서버 식별자로만 한다.** 예매 식별자, 없으면 작업 식별자를 쓰고 SN·타이밍·인덱스로
   추정하지 않는다. 귀속할 수 없는 프레임은 어느 행에도 적용하지 않는다 `[추론]`.
4. **발권 가능 판정은 지금 연결에서 받은 상태만 쓴다.** 표시는 마지막 값을 유지해 판정과 표시를 같은
   gate로 묶지 않는다 `[추론]`.
5. **서버가 준 숫자는 그대로 표시하고 판정에는 쓰지 않는다.** 채우거나 숨기거나 정규화하지 않으며
   `없음`과 `0`을 구분한다 `[추론]`.

**관측의 부재는 실패가 아니다.** 결과를 모르는 행을 진행 중·중단·빈 값으로 추정하지 않고 별도 표기로
드러낸다 `[추론]`.

## 5. 현재 저장소 범위와 상태 소유권

- 현재 범위: 공연·회차 검색, 행 선택, 프린터 선택, 확인 alert, 발권 popup, 미리보기와
  `테스트 발권`, 활성화된 `발권 시작하기` 버튼까지 `[선언]`.
- 현재 제외: 버튼 실행, 프레임 수신, 진행·완료·취소·재시작, SSE, 작업 저장소와 cache 결과 `[선언]`.
- 호출 전 검색 조건은 route/feature, 행과 프린터 선택·preview open 상태는 feature/dialog local이 소유한다 `[선언]`.
- 선택 갱신과 alert는 서로의 상태를 쓰지 않으며, 현재 공연의 발권 가능 기간과 preview 준비 여부를
  feature가 검증한다 `[추론]`.
- 이 축을 열 때는 3절 실패와 4절 다섯 규칙을 먼저 대조하고, 두 번째 코드 consumer 없이 새 shared
  추상화를 만들지 않는다 `[선언]`.

## 6. 실시간 축을 열기 전 미확인

1. 신규 서버가 주는 프린터·예매·작업 식별자와 실시간 protocol·인증 갱신 방식 `[미확인]`.
2. 종료 공연 판정에 쓰는 권위 있는 기간과 발권 가능 상태 `[미확인]`.
3. 프린터 상태 확인 timeout과 오류 표기의 제품 문구 `[미확인]`.
4. 미수신·귀속 불가·결과 미상 행에 쓸 별도 표기 어휘 `[미확인]`.
5. 작업 취소를 허용하는 식별자와 동시 운영자·프린터 점유 규칙 `[미확인]`.
