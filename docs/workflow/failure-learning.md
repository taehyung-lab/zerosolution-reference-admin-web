# 실패에서 다음 작업으로

검증 실패·근거 충돌·작업 누락을 실제로 만났을 때 읽는다. 정상 작업의 절차는
[AGENTS.md](../../AGENTS.md#설계와-작업-기록)가 소유한다. 실패 기록은 현재 판단의 정본이 아니다.

## 한 작업 기록에 남길 것

기존 대화나 작업 기록에 아래 내용을 덧붙인다. 새 보고서·실패 원장·학습 원장을 따로 만들지 않는다.
후속 세션에 인계하거나 재발을 추적해야 하면 `.ai-work/tasks/<작업명>.md` 한 파일을 사용한다.
이 경로는 Git에서 제외되므로 다른 checkout의 동료에게는 필요한 기록을 명시적으로 전달한다.
공유해야 할 재발 방지는 코드·테스트·계약·fact 등 추적되는 기존 소유자에 반영한다.

| 항목 | 무엇을 기록하나 |
| --- | --- |
| 요구·기대·실제 | 어떤 성공 조건에서 무엇이 달랐는가 |
| 수행 주체·발생 위치·발견 | 실제 담당자/에이전트와 단계·파일, 발견한 검사/관찰을 구분한다. 모르면 미확인 |
| 원인과 근거 | 재현 입력·URL·명령·출력 또는 diff로 원인을 설명한다. 추정은 추정으로 표시 |
| 수정 소유자·조치 | 어느 코드·테스트·계약·fact·환경을 왜 바꿨는가 |
| 재확인·남은 것 | 같은 상황과 필요한 연결 경로의 결과. 미해결이면 재개 조건과 담당을 남김 |

로그 원문은 저장소 밖에 두고 기록에는 재현에 필요한 안전한 요약과 위치만 남긴다. secret·개인정보를
적지 않는다. 원인을 확인하기 전 성공 조건·단언을 완화하지 않는다. 재실행 통과만으로 원인이나 해결을
확정하지 않는다. 원래 기대가 잘못됐다면 제품 근거나 사용자 결정으로 바로잡고 변경 이유를 기록한다.

## 원인에 따라 돌아갈 곳

발견한 곳과 원인을 가진 곳은 다를 수 있다. 검토자가 결함을 발견한 것은 검토 실패가 아니다.
“에이전트가 놓쳤다”에서 멈추지 말고 문서를 못 찾았는지, 읽고 잘못 적용했는지, 문서가 틀렸는지 확인한다.

| 확인된 원인 | 수정할 소유자 |
| --- | --- |
| 요구 오해·누락 | 작업의 요구와 성공 조건. 원문 요구를 새로 찾았으면 해당 fact에도 근거를 수용 |
| 제품 근거 없음·낡음·충돌 | 해당 fact와 [근거 정책](../../product/policies/evidence.md). 원문·사용자 결정으로 갱신하고, 답이 없는 영향 부분만 보류 |
| 필요한 계약을 찾지 못함 | description·진입 링크. 경로는 명확했는데 수행자가 건너뛰었다면 기록에 그 근거를 남기고 다시 적용 |
| 계약이 없거나 모호하거나 서로 충돌 | 그 판단을 소유한 계약을 교체·명료화. 다른 계약에 같은 경고를 복제하지 않음 |
| 상태 중복·불필요한 계층·잘못된 공용화 | 설계와 구현. [공용 승격](../../.agents/skills/source-structure/references/promotion.md)은 실제 공유 판단이 필요할 때만 확인 |
| 계약은 명확하지만 구현이 어김 | 코드와 가장 가까운 회귀 테스트. 기존 계약을 루트에 다시 쓰지 않음 |
| 검사가 틀린 결과를 통과시키거나 옳은 결과를 거부 | 기존 검사의 단언·관찰 방법. 재발 방지가 필요하고 기존 검사로 잡지 못할 때 새 검사 선택 |
| 실행 수단·포트·자격증명·도구 | 환경과 실행 안내. 실행하지 못한 결과는 미확인 |

색인에 항목이 없으면 선언된 source owner까지 확인한다. 한 원문이 여러 화면을 담으면 해당 화면만
읽는다. 이름이 소유자를 오도하면 실제 route·소비자를 추적한다. 코드·테스트 통과로 제품 사실을 만들지
않는다. 원인이 여러 곳이면 각각의 근거와 조치를 기록하고, 닫히지 않은 원인은 미확인으로 남긴다.

## 다음 작업에서 달라져야 하는 것

조치 후 같은 재현과 영향을 받는 경로를 다시 확인한다. 기존 검사가 충분하면 재사용한다. 코드·테스트로
설명되지 않는 재사용 가능한 판단만 기존 계약에 남기고, 중요한 선택의 이유는 필요할 때 ADR에 남긴다.
전역 게이트 추가·퇴출은 [기존 게이트 수명 기준](../../scripts/contracts/README.md#gate-lifecycle)을 따른다.

기록만 남겼으면 **기록됨**, 원인 소유자를 고쳤으면 **조치됨**, 원래 실패 조건과 영향을 받는 경로를
확인했으면 **재확인됨**이다. 기록 작성이나 재실행 한 번을 재발 방지 완료로 취급하지 않는다.

| 다음 작업의 상황 | 읽을 것 |
| --- | --- |
| 새 작업·해결된 실패와 유사한 작업 | 현재 작업에 해당하는 갱신된 정본·코드·테스트. 과거 실패 기록은 필수 아님 |
| 미해결 작업을 이어받음 | 인계자가 지정한 해당 작업 기록과 재개 조건. 저장소 밖 기록은 위치 또는 내용을 함께 전달 |
| 같은 증상이 재발하거나 현재 근거와 충돌 | 관련 기록의 이전 가설·조치·재확인을 비교. 과거 결론도 현재 증거로 재검토 |

작업 시작마다 실패 원장을 전부 읽거나 성공한 항목을 전부 재검사하지 않는다. 실패를 찾는 단서는
현재 요구·관련 계약·검사 결과이며, 과거 기록을 외웠는지가 아니다. 조치가 코드·검사로 표현되면 실행
소유자에 두고, 판단이 필요할 때만 기존 계약을 고친다. 다음 독립 작업에서 재발하지 않았는지는 별도
관측이며, 한 번의 성공으로 일반화하지 않는다.
