# 전시 배너 등록·수정

## 구성

등록(7.1.3)·수정(7.1.4) frame 은 같은 `기본정보` 섹션을 그린다. 수정은 값이 채워져 있다.

| 항목 | 등록 frame | 수정 frame | Notion |
| --- | --- | --- | --- |
| 구분 * | 입력 상자에 `홈` | `홈` | `필수선택, 직접선택` |
| 게시순서 * | 빈 입력, 아래 안내 `숫자만 입력 가능합니다.` | `1` | `필수입력, 직접입력` · `입력가능문자 : 숫자` · `입력가능글자수 : 1~3자리` |
| 배너명 * | placeholder `500자 내외` | `광고형 배너` | `필수입력, 직접입력` |
| 이동경로 | 소제목, 아래 `유형 *` select `APP 내부` \| `URL *` placeholder `URL` | `APP 내부` \| `//app/bbs/notice/123` | — |
| 이미지 * | placeholder `파일선택` + `⊕ 파일선택`, 안내 `권장 사이즈 : 가로 {n}px * 세로 {n}px   지원확장자 : png, 1MB 이하` | 같은 입력 + 파일 chip `file_name.xlx ⓧ` | — |
| 게시기간 * | 빈 입력 + 달력 | `2026-06-01 12:00:00 ~ 2026-12-31 12:00:00` + 달력 | `필수선택, 직접선택` · `시작 년월일~종료 년월일 선택` · `default : 미선택` |
| 게시 상태 * | **그리지 않음** | 게시기간 오른쪽 select `게시중` | 수정: `대기, 게시중, 종료 중 택1`(화면 간) |
| 하단 | 검정 `저장`, 흰 `취소` | 같음 | `저장 버튼` |

Case 정의 7.1.3.1: `유형 *` 옵션 `APP 내부 · 외부 경로`, 이미지 업로드 뒤 chip `file_name.png ⓧ`,
`게시상태 *` select 옵션 `대기 · 게시중 · 종료`(값 없음).

## 동작

| 동작 | 관찰 | 출처 |
| --- | --- | --- |
| 저장 | `[저장 확인 alert]` → `확인 : 저장이 완료되고, 저장 완료 alert 제공` → `[저장 완료 alert]` | Notion 화면 간 |
| 저장 완료 확인 | `확인 : 등록된 조회 화면으로 이동` | Notion 화면 간(추론) |
| 검증 | `필수정보 미입력시, 해당 필드 강조 처리` · `입력 오류시, 해당 필드 강조 처리` | Notion 화면 간 |
| 취소 | `취소할 경우 입력된 정보는 모두 삭제됩니다. / 입력을 취소하시겠습니까? / 확인, 취소` | Notion |

## 추론

1. 저장 완료 뒤 목적지는 등록·수정 모두 조회다. 서버가 새 ID 를 돌려주지 않는 동안 등록은 조회할 레코드가 없어 목록으로 간다.
2. 배너명 글자수는 이 화면 절에 없고, placeholder `500자 내외` 와 화면 간 원문 `입력가능글자수 : 1~500자` 행이 말한다 — 입력 `maxLength` 500 으로만 건다.
   화면 간 원문은 같은 `전시 > 배너` 를 `입력가능글자수 : 제한없음`·`입력가능문자 : 제한없음` 행에도 올린다 — 어느 필드의 문장인지 전사가 가르지 않는다(**충돌**, 미확인 8).
3. 게시순서 형식 오류 문구는 frame 안내 문장 `숫자만 입력 가능합니다.`, 이미지 오류 문구는 안내의 `지원확장자 : png, 1MB 이하` 를 쓴다. 필수 누락은 공용 문구.

## 미확인

| # | 무엇 | 답에 따라 달라지는 것 | 누구에게 |
| --- | --- | --- | --- |
| 1 | 등록의 `게시 상태` — 등록 본 frame 은 그리지 않고 등록 Case 정의는 `게시상태 *` select 를 그린다. 구현은 Case 정의를 따라 값 없는 필수 select 로 둔다 | 등록 입력·서버 기본 상태 | 제품·디자인 |
| 2 | 이미지 업로드가 별도 요청인지 한 multipart 저장인지, 저장 응답 모양 | 저장 mutation | 백엔드 |
| 3 | 게시기간 시각 — frame 은 `12:00:00` 을 그리고 Notion 은 `년월일` 선택이라 적는다. 구현은 날짜만 받는다 | 입력·요청 정밀도 | 제품 소유자 |
| 4 | `1MB` 가 1,000,000 바이트인지 1,048,576 바이트인지. 구현은 1,048,576 | 용량 경계 | 제품·서버 |
| 5 | `{n}` 권장 가로·세로 값(시나리오 원장 미확인 1) | 안내 문구·검증 | 디자인 |
| 6 | URL 형식 규칙(APP 내부 `//app/...` 과 외부 경로의 형식 검증) | URL 검증 | 제품 소유자 |
| 7 | 「배너정보를 수정할 수 있다」 원문 절(전사에 없음) | 수정 전용 규칙 | Notion 원문 |
| 8 | 배너명 글자수 — 화면 간 원문의 `1~500자` 행과 `제한없음` 행이 모두 `전시 > 배너` 를 대상으로 적는다(추론 2). URL 에 `제한없음` 이 걸리는지도 같은 질문이다 | 배너명·URL 길이 | Notion 원문(배너 등록 절) |

## 보류

- `{n}` 크기 검증(미확인 5), URL 형식 검증(미확인 6)은 만들지 않았다.
