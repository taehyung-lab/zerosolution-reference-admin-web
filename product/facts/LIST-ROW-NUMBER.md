# 목록 No. 컬럼

## 관찰

| frame | 결과 건수 | No. 컬럼 위에서 아래로 |
| --- | --- | --- |
| 5.2.1 공연목록 (보기 100, 1페이지) | `검색결과 : 1,000` | `1000` · `999` · `998` … `989` 뒤 `- 이하 생략 -` |
| 9.1.1 게시판 리스트 | `검색결과 : 3` | `3` · `2` · `1` |

두 frame 모두 첫 행 번호가 **결과 건수와 같고** 한 행마다 1씩 줄어든다. 8.1 APP PUSH 는 옛 원장
(`docs/reference/zero-sol/08-promotion.md`)이 `No.` 역순이라고 적는다 — 이 작업에서 8.1 frame 은 열지 않았다.

## 정책

- `No.` 는 결과 건수에서 내려가는 번호다. 1페이지 첫 행이 결과 건수, 마지막 페이지 마지막 행이 1이다.
- 페이지를 넘겨도 이어진다: `결과 건수 − (페이지 − 1) × 보기 − 페이지 안 순서(0부터)`. — **추론**
  (관찰된 frame 은 모두 1페이지다. 2페이지 이후의 식은 1페이지 관찰과 페이지 번호의 뜻에서 나온 것이다)
- 번호는 보이는 행 순서에 붙는다. 서버 레코드 ID 가 아니다. — **추론**(두 frame 모두 번호가 결과 건수에서
  빈틈없이 이어져 레코드 고유 번호로 읽을 근거가 없다)
