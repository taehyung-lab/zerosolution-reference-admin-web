# 공연 조회

## 관찰

두 상태 frame 이 있다. 가르는 것은 **입장안내정보의 입력 여부**다.

| 상태 | 화면 |
| --- | --- |
| 입력전 (default) | 입장안내정보 자리에 `등록된 정보가 없습니다.` 와 수정 진입 |
| 입력후 | 도면 다운로드 · 입력 방식 · 게이트/구역 · **업데이트 이력** |

읽기 섹션의 순서: 구분/공연유형 → **언어 tab(한국어·일본어·영어)** 안의 공연명·부제·출연자·기획/주관
→ 회차별 공연일 → 이벤트명/입퇴장일시 → 공연장 → 좌석수 및 회차별 판매·미판매 → 등급.
**모두 읽기 전용이다.**

## 정책

- 목록의 행을 활성화하면 그 ID 의 조회로 이동하고, 브라우저 뒤로 가기는 목록의 검색 조건을 복원한다.
- 이력은 확인한 변경(도면명 등)을 표시하고, 미확정 필드·구조의 원문 값은 표시하지 않는다.
- 입력전 예시에는 이력 행이 없어 이력 절을 렌더하지 않는다.
- 이 admin 에는 **공연 자체를 등록하는 화면이 없다.** 공연은 다른 곳에서 만들어진 값을 읽는다는
  설명은 원문에서 관찰되지 않은 추론이므로 근거로 쓰지 않는다 — 관찰된 사실은 "등록 화면이
  원장에 없다" 까지다.

## 상태와 소유자

| 값 | 소유자 |
| --- | --- |
| 상세 레코드 | Query |
| 어떤 레코드를 여는가 | route params |
| 언어 tab 선택 | 가장 가까운 화면 component |
