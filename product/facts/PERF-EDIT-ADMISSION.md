# 공연 수정 — 입장안내정보

## 관찰

**독립된 수정 화면이다.** frame 이름은 `5.2.3. 공연 수정`, 제목은 `공연 수정`, breadcrumb 은
`공연 > 공연목록 > 조회 > 수정` 이다. 화면은 편집 섹션 `입장안내정보` 와 읽기 섹션 `기본정보` 두 개로
이루어지고, 조회에 있는 `업데이트 내역` 은 이 화면에 없다.

**편집 대상은 `입장안내정보` 섹션 하나다.** 나머지(기본정보 · 공연일 회차 · 이벤트 · 공연장 ·
좌석수 · 등급)는 읽기다.

편집 섹션의 구성:

| 항목 | 관찰된 것 |
| --- | --- |
| 안내 도면 | `파일선택` 입력 + 버튼, 그 아래 hint `지원확장자 : *, *MB 이하`(값이 `*` 인 미완성 표기), 선택 후 파일명 chip(ⓧ). **필수 1개, 마지막에 선택한 파일로 교체** |
| 입력 방식 | select — `구역` / `등급` 중 하나. **default 는 `구역`** |
| 반복 행 | 게이트(필수 select) + 입력 방식에 따라 구역(필수 input) 또는 등급(필수 다중 선택) |
| 행 조작 | 행마다 `삭제`, **마지막 행에만 `추가`**. `추가` 는 행을 **하단에** 더한다 |
| 게이트 | 그 공연에 설정된 **공연장으로 등록된 게이트** 중 택1. 최소 1행 |
| 구역 | 필수 · **20자 이하** · 문자 제한 없음. 동일 게이트라도 구역은 행마다 개별 입력 |
| 등급 | 그 공연에 등록된 등급 중 다중 선택. 펼친 목록의 첫 행이 `전체` 이고 닫힌 표시는 `(등급명), (등급명)` |
| 행 아래 안내 | 구역: `* 게이트에 따라 안내할 관람객의 구역을 입력해주세요. 동일 게이트이더라도 구역은 개별로 입력해주세요.` / 등급: `* 게이트에 따라 안내할 관람객의 등급을 선택해주세요.` |
| 섹션 액션 | 섹션 안 가운데에 `저장`(primary) · `취소` |

읽기 섹션의 순서: 구분/공연유형 → **언어 tab(한국어·일본어·영어)** 안의 공연명·부제·출연자·기획/주관
→ 회차별 공연일 → 이벤트명/입퇴장일시 → 공연장 → 좌석수 및 회차별 판매·미판매 → 등급.

**두 frame 이 행의 열 순서를 다르게 그린다.** `5.2.3` 은 `구역` → `게이트` 로, `5.2.3.1 Case 정의` 는
`게이트` → `구역`(등급) 로 그린다. Notion 원문의 서술(`게이트, 구역 입력 필드가 제공됨`)과 조회 화면의
표 머리(게이트 | 구역)는 후자와 같아 **게이트를 앞에 둔다** — 5.2.3 의 순서는 그 frame 하나뿐인
표기로 보고 채택하지 않았다(추론).

## 정책

- 저장: `유효성 체크` → Case01 **필수 미입력이면 해당 필드 강조**(확인창 없음) → Case02 모두 유효하면
  **저장 확인 alert**(`저장하시겠습니까?` · 확인/취소) → 확인 시 **저장 완료 alert**(`저장이되었습니다.`
  · 확인) → 확인 시 **조회 화면으로 이동**. 저장 확인의 취소는 alert 만 닫고 현 상태를 유지한다.
- 취소: **취소 alert**(`취소할 경우 입력된 정보는 모두 삭제됩니다.` / `입력을 취소하시겠습니까?` ·
  확인/취소) → 확인 시 조회 화면으로 이동, 취소 시 현 상태 유지. 원문은 이 alert 에 입력 여부 조건을
  달지 않는다 — 공용 폼 계약은 clean 이면 묻지 않고 나가므로 **그 지점에서 계약이 원문보다 좁다.**
- 조회 화면의 `수정` 버튼은 **"클릭 시 수정 화면으로 이동"** 이고, 5.2.3 frame 이 그 화면이다.
  2026-09-08 에 남긴 "Figma 는 섹션 단위 편집" 관찰은 조회 frame 만 보고 쓴 것으로, 2026-09-17
  재관찰에서 **독립 화면으로 정정**했다. 저장·취소가 섹션 안에 있는 것과 화면이 독립인 것은 별개다.
- 저장 입력은 **이 섹션이 자기 필드만** 싣는다. 읽기 섹션의 값은 저장 입력에 섞이지 않는다.
- 반복 행의 값과 오류는 **행을 따라간다.** 배열 index 를 행 정체성으로 쓰면 삭제 뒤 오류가 다른
  행으로 옮겨간다.
- 언어 tab 은 읽기 섹션의 표시 상태다. tab 전환이 편집 중인 입력을 잃게 하지 않는다.

## 상태와 소유자

| 값 | 소유자 |
| --- | --- |
| 상세 레코드(읽기 섹션의 모든 값, 게이트·등급 선택지) | Query |
| 입장안내 반복 행 · 파일 · dirty · 검증 | 이 섹션의 폼 |
| 언어 tab 선택 | 가장 가까운 화면 component |
| 어떤 레코드를 여는가 | route params |

## 전이

```text
조회(입력전: 「등록된 정보가 없습니다.」 + 수정) → 수정 진입 → 빈 폼(입력 방식 `구역`, 행 1개)
조회(입력후: 도면 · 입력방식 · 게이트/구역 · 업데이트 이력) → 수정 진입 → 값이 채워진 폼
편집 → 검증 실패면 그 자리에서 거절(확인창 없음) → 저장 확인 → 저장 → 저장 완료 → 조회로 이동
편집 → 취소 → 확인 → 조회로 이동
```

입력전 예시에는 이력 행이 없어 이력 절을 렌더하지 않는다.

## 미확인

| # | 무엇이 미확인인가 | 답에 따라 무엇이 달라지나 | 누구에게 묻나 |
| --- | --- | --- | --- |
| 1 | 업로드 지원 확장자와 용량 상한 | 파일 입력의 accept 와 안내 문구 | 제품 — **원문이 `지원 확장자 : 개발 확인 필요`** 라고 적고 frame hint 도 `*, *MB 이하` 다. 값이 정해지기 전까지 안내 문구를 그리지 않는다 |
| 2 | 입력 방식(구역↔등급) 전환 시 반대 값의 보존 여부 | 전환 후 재전환의 입력 상태 | 제품 — 원문에 없다 |
| 3 | 섹션별 저장의 mutation 범위와 실제 endpoint, 도면 업로드 방식 | 요청 payload 와 성공 후 무효화 | 서버 계약 |
| 4 | 게이트·등급의 서버 식별자 계약 | 폼 값이 표시 문자열인지 ID 인지 | 서버 계약 |
| 5 | 반복 행의 최대 개수 | 추가 버튼의 상한 | 제품 — 원문은 최소(1개 이상)만 적는다 |
| 6 | 마지막 한 행의 `삭제` | frame 은 행이 하나일 때도 `삭제` 를 그리는데 원문은 `1개 이상의 게이트 필수 선택` 이다. 지운 뒤 상태가 무엇인지 | 제품 |
| 7 | 등급 다중 선택의 `전체` 행 | 전체 선택 토글인지 "전체" 라는 값인지 | 제품 — frame 에만 있고 원문 서술이 없다 |
| 8 | 빈 이력 절의 표시 정책 | 이력이 없을 때 절을 그리는가 | 제품 |

미확인은 **그 부분만 보류**한다. 확인된 나머지는 진행한다. 값을 지어내지 않는다.

## 현재 코드

수정 route·폼·저장이 구현됐다(2026-09-17). 게이트 선택지는 상세 레코드가 싣고, 저장은 이름 붙은
요청 함수까지 도달한다 — 실제 endpoint·DTO 는 위 [미확인](#미확인) 3·4 다.
보류한 것: 파일 입력의 `accept` 와 지원 확장자 안내(미확인 1), 등급 목록의 `전체` 행(미확인 7),
행이 하나일 때의 `삭제`(미확인 6 — 최소 1행을 지키려고 그리지 않는다).
이 절의 수명은 [근거 수명 규칙](../policies/evidence.md)이 소유한다.
