# 게시물 등록·수정

## 관찰

breadcrumb 는 등록 `커뮤니티 > 게시물 > 등록`, 수정 `커뮤니티 > 게시물 > 조회 > 수정`.
두 frame 은 `기본정보` 한 섹션을 같은 항목·같은 순서로 그리고 수정만 값이 채워져 있다.
하단은 `저장`(primary) · `취소`.

### 기본정보

| 항목 | 관찰된 것 |
| --- | --- |
| 구분 * | select — 일반 · 상담 · 공지사항. 등록 frame 의 닫힌 값은 `일반` |
| 게시판 * | select — 닫힌 값 `선택`. 수정 frame 은 `1:1상담` |
| 카테고리 * | select — `선택` + `{카테고리명}` 반복. 고른 게시판이 소유한 목록이다 |
| 작성자 검색 | 돋보기 입력 + **`본인으로 작성하기` checkbox**(등록 frame 에만 있고 체크돼 있다) |
| 회원유형 / 회원등급 | 읽기 전용. 등록 frame 은 `운영자`/`운영자`, Case 는 `일반회원` |
| 작성자 | 읽기 전용. Case 는 `김땡땡(your****@email.com)` |
| 답변받을 이메일 | 등록 frame 은 **비활성**, 수정 frame 은 `답변받을 이메일 *` 입력(`your1234@email.com`) |
| 제목 * | 입력 |
| 내용 * | 넓은 입력. Case 상단에 `html editer` 라고만 적혀 있다 |
| 파일첨부 | `파일선택` 입력 + `⊕ 파일선택` 버튼 + 안내 `권장 사이즈 : {1MB} 이하`. 수정 frame 은 **`file_name.jpg` 두 줄 + ⊗** |
| 등록일 * | 달력 입력. 수정 frame 값 `2026-06-01 12:00:00` |
| 조회수 | 입력 상자. 등록 `0`, 수정 `10` |
| 게시상태 | select — 게시 · 게시안함. 등록 frame 의 닫힌 값은 `게시` |

Case 정의는 `기본정보` 아래에 **`팝업 설정`** 섹션(팝업 사용 * · 다시보지않기 사용 * · 노출 위치 *)을
더 그린다. 등록·수정 frame 자체에는 그 섹션이 없다.

### 동작 (Notion)

- `저장 버튼 → 클릭시, 유효성 체크 → Case02. 정상`.
- `기본정보 영역 → 등록일 → 필수선택, 직접선택`, `년월일 시분초 선택`.
- `기본정보 영역 → 작성자 → 작성자 검색 버튼`.
- `회원등급 → 전체, 선택 중 택1 → 선택을 선택한 경우 상세 회원 등급 리스트를 다중선택 가능`
  (작성자 검색 팝업의 조건이다).

## 미확인

| # | 무엇이 미확인인가 | 답에 따라 달라지는 것 | 누구에게 |
| --- | --- | --- | --- |
| 1 | 파일첨부의 **다중 첨부 규칙·허용 확장자·용량 상한의 출처**. 안내의 `{1MB}` 는 치환 자리로 보이고 게시판의 `파일첨부 용량제한` 이 후보지만 원문이 잇지 않는다 | 입력의 개수·검증·업로드 계약 | 제품 소유자 |
| 2 | `조회수` 입력이 **편집 가능한 값인지**. 등록에서 0 을 넣는 의미가 원문에 없다 | 입력인지 읽기 전용인지 | 제품 소유자 |
| 3 | 등록일의 **시·분·초**. Notion 은 `년월일 시분초 선택` 이라 적고 저장소의 공용 날짜 입력은 날짜까지만 받는다 | 공용 입력을 넓힐지, 화면이 따로 조립할지 | 제품 소유자 + 공용 UI 계약 |
| 4 | `내용`의 **HTML 에디터**가 허용하는 요소·저장 형식 | 입력 위젯과 저장 값 | 제품 소유자 |
| 5 | `팝업 설정` 섹션의 **발동 조건**(게시판의 `팝업` 설정인지 구분인지)과 `노출 위치` 의 전체 목록 | 섹션을 그리는 조건과 옵션 | 제품 소유자 |
| 6 | 카테고리가 `*` 필수인데 **카테고리를 쓰지 않는 게시판**에서는 무엇이 되는지. 목록 표는 카테고리 `-` 를 그린다 | 필수 여부의 조건 | 제품 소유자 |
| 7 | `답변받을 이메일` 이 등록에서 비활성인 조건(작성자가 운영자여서인지 `본인으로 작성하기` 때문인지) | 입력의 활성·필수 규칙 | 제품 소유자 |
| 8 | 저장 성공 뒤 이동 목적지(목록인지 조회인지). 원문은 `Case02. 정상` 까지만 적는다 | 저장 후 navigation | 제품 소유자 |
| 9 | `작성자 검색` 팝업(9.2.5.4)의 구성과 **확인 시 반환값**. 팝업 안에 독립 목록(라디오 APP 회원·운영자 + 기간 + 검색어 + 가입방법·계정 상태·활동제한 + 결과 표 + 페이지)이 있고 단일/다중 선택이 원장에서 미확인이다 | 다른 회원을 작성자로 고를 수 있는지, 그때 답변받을 이메일이 어디서 오는지 | 제품 소유자 + 그 frame |

## 보류

- 파일첨부 입력 — 미확인 1 이 다중 첨부·용량 출처·업로드 계약을 답할 때까지 그리지 않는다.
- 조회수 입력 — 미확인 2 가 편집의 의미를 답할 때까지 그리지 않는다.
- 등록일의 시·분·초 — 미확인 3 이 닫히고 공용 날짜·시각 입력을 넓히기로 정하면 넣는다. 지금은 날짜까지 받는다.
- 내용의 HTML 에디터 — 미확인 4 가 허용 요소·저장 형식을 답할 때까지 여러 줄 입력이다.
- `팝업 설정` 섹션 — 미확인 5 가 발동 조건과 `노출 위치` 목록을 답할 때까지 그리지 않는다.
- `작성자 검색` 팝업(9.2.5.4 검색전/검색후/Case) — 미확인 9. 그때까지 등록은 `본인으로 작성하기` 경로만이며, 그래서 등록 화면은 작성자 행과 `답변받을 이메일`(등록 frame 에서 비활성)도 그리지 않는다.
