# 게시물 목록

## 관찰

### 진입·구성

LNB 는 `커뮤니티 > 게시판 · 게시물` 두 항목이다. breadcrumb 는 `커뮤니티 > 게시물`, 제목은 `게시물`.

검색 패널은 접기/펼치기 하나(`검색` + `＋`/`－`)를 가진다. 리스트 frame 은 기간·검색어 두 행만 그리고
나머지 행은 Case 정의 frame 이 열거한다 — 두 frame 을 합친 검색 영역이 아래 표다.

**검색 전 frame 이 없다.** 결과가 있는 frame 하나뿐이다.

### 검색 조건

| 행 | 관찰된 것 |
| --- | --- |
| 기간 | 기준 **등록일 · 최근업데이트일**, preset `전체 / 1년 전 / 6개월 전 / 3개월 전 / 1개월 전 / 7일 전 / 어제 / 오늘` + 범위 |
| 검색어 | 대상 **내용 · 제목**(닫힌 값 `내용`), 다중 키워드 허용, chip 표기 `내용 : 공지사항` |
| 구분 | 다중 선택 — 전체 \| 일반 · 상담 |
| 게시판 | 단일 select — `전체` + **서버가 주는 게시판명 목록**. Notion: 「[게시판]에 등록된 게시판 중 [사용상태 : 사용]으로 설정된 리스트 중 택1」, `default : 전체` |
| 회원유형 | 단일 select — 전체 · 비회원 포함 · 전체회원 · 운영자 |
| 답변상태 | 다중 선택 — 전체 \| 대기 · 검토중 · 완료 |
| 게시상태 | 다중 선택 — 전체 \| **사용 · 사용안함** |

다중 선택 셋은 **default 가 전체**다(Notion 이 구분·답변상태·사용상태를 그렇게 적는다).
하단은 `검색`·`초기화`.

### 보기·정렬

`보기` 목록 100 · 200 · 300 · 400 · 500 · 700 · 1000, **100 이 굵게** 그려진 기본값이다.
`정렬` 목록 14개, 화면 순서대로 **등록일**(굵게) · 최근업데이트일 · 구분 · 게시판 · 제목 · 내용 ·
회원유형/회원등급 · 작성자 · 좋아요 · 싫어요 · 평점 · 댓글 · 조회수 · 게시상태.
표의 `카테고리`·`답변상태` 는 이 목록에 없다.

### 결과 toolbar

왼쪽 `검색결과 : 1,000`, 그 아래 `보기`·`정렬`. 오른쪽 `선택 ▾`·`변경`·`등록`.
`선택 ▾` 은 2단 cascade `게시상태 >` → **게시 · 게시안함** 하나뿐이다.

### 표

행 checkbox가 있고 컬럼은 순서대로
구분 · 게시판 · 카테고리 · 제목 · 내용 · 회원유형/회원등급 · 작성자 · 좋아요 · 싫어요 · 평점 ·
댓글 · 조회수 · 답변상태 · 게시상태 · `등록일/최근업데이트일`.

### 표시 형식

| 자리 | 관찰된 것 |
| --- | --- |
| 빈 값 | `-` — 카테고리·제목·좋아요·싫어요·평점·답변상태에서 실제로 그려진다. 댓글·조회수는 모든 예시 행이 숫자다 |
| 작성자 | `이름(연락처)`. APP 회원은 **마스킹된 이메일** `김땡땡(your****@email.com)`, 운영자는 **마스킹하지 않은 아이디** `김담당(idididid123)` |
| 회원유형/회원등급 | APP 회원 행은 `일반회원/일반회원`, 운영자 행은 `운영자` 하나 |
| 내용 | 두 줄로 줄이고 그 아래 **썸네일 행**(회색 자리표시자 2개) |
| 게시상태 | 표는 **게시 · 게시안함**. 같은 축을 검색 영역은 `사용 · 사용안함` 으로 그린다 |
| 등록일/최근업데이트일 | 한 셀에 두 줄, 각 줄 `2026-06-01 12:00:00` |

### 동작 (Notion)

- 행 클릭 → 조회 화면 이동.
- `등록` → 등록 화면 이동.
- 일치하는 결과가 없으면 안내 메시지.
- 일괄변경 3단계: `변경할 항목을 선택해주세요.` / 확인 → `선택 항목을 변경하시겠습니까?` /
  확인 → `변경되었습니다.` → 확인하면 `변경 상태로 화면 갱신됨`, 취소는 현상태 유지.

## 미확인

| # | 무엇이 미확인인가 | 답에 따라 달라지는 것 | 누구에게 |
| --- | --- | --- | --- |
| 1 | **진입 즉시 조회인가 검색 후 조회인가.** Notion 은 `초기화 → … 검색 전 상태로 변경` 이라 검색 전 상태를 말하고, Figma 는 검색전 frame 없이 결과 frame 하나만 그린다. 같은 파일에서 gate 가 있는 표면(9.2.5.4 작성자 검색)은 검색전·검색후 frame 을 따로 그린다 | 진입 시 조회 여부, URL 의 검색 의도 표식, 초기화 뒤 결과가 남는지 | 제품 소유자 |
| 2 | 검색 영역 `회원유형`(비회원 포함·전체회원·운영자)과 표의 `회원유형`(일반회원·운영자)이 **같은 축인지**. 두 어휘가 겹치지 않는다 | 필터가 표의 값을 어떻게 좁히는지, 서버 enum 이 하나인지 둘인지 | 제품 소유자 |
| 3 | 같은 `게시상태` 축을 검색은 `사용/사용안함`, 표·일괄변경은 `게시/게시안함` 으로 부르는 것이 **라벨 두 벌인지 값 두 벌인지** | 라벨 키를 하나로 합칠 수 있는지 | 제품 소유자 |
| 4 | `좋아요·싫어요·평점` 이 `-` 인 조건(게시판 설정이 끈 경우인지, 값이 없는 경우인지) | 0 과 `-` 를 나누는 규칙 | 제품 소유자 |
| 5 | 정렬을 **헤더에서도** 고를 수 있는지. frame 은 정렬 표시를 마지막 컬럼에만 그렸고 정렬 목록은 14축을 연다 | 헤더 정렬 버튼을 다는 컬럼 집합 | 디자인 원문 소유자 |
| 6 | 표의 `회원유형/회원등급` 전체 enum. frame 이 그린 값은 유형 `일반회원`·`운영자`, 등급 `일반회원` 뿐이다 | 라벨 집합과 서버 enum | 제품 소유자 |
| 7 | 정렬 default 의 `마지막으로 설정한 값` 보관 여부(Notion `등록일 or 마지막으로 설정한 값`). 보기도 같다 | 사용자별 보기·정렬 보관 기능의 유무 | 제품 소유자 |
| 8 | 썸네일 이미지의 출처·개수 상한 | 표 셀의 이미지 렌더 규칙 | 제품 소유자 |
