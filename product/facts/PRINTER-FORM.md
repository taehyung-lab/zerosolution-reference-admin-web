# 스마트프린터 등록·수정

## 관찰

등록과 수정의 **항목·필수·선택지가 같다.** `기본정보` 섹션이 2열이다.

| 자리 | 항목 | 필수 | 관찰된 제약·기본값 |
| --- | --- | --- | --- |
| 1 좌 | 기기명 | **필수** | `(1~100자 내외)` |
| 1 우 | 시리얼번호 | **필수** | `(1~100자 내외)` |
| 2 좌 | 모델명 | | `(100자 내외)` |
| 2 우 | 제조사 | | |
| 3 | 구매일 | | 달력 |
| 4 좌 | 보관위치 | | |
| 4 우 | 상태 | **필수** | 정상 · 고장 · 수리중. **기본 정상** |
| 5 | 조치사항 | | **여러 줄 입력** |
| 6 좌 | 용도 | **필수** | 내부발권용 · 현장발권용. **기본 내부발권용** |
| 6 우 | 사용상태 | **필수** | 사용 · 사용안함. **기본 사용** |

하단에 `저장` · `취소`.

## 정책

- `저장` 은 먼저 유효성을 확인한다.
- `취소` 는 입력 취소 alert 로 묻는다.

## 상태와 소유자

| 값 | 소유자 |
| --- | --- |
| 입력 값·dirty·필드 오류 | 이 화면의 폼 |
| 수정이 채우는 레코드 | Query |
| 저장·취소의 목적지 | route |

## 미확인

| # | 무엇이 미확인인가 | 답에 따라 무엇이 달라지나 | 누구에게 묻나 |
| --- | --- | --- | --- |
| 1 | **제조사 · 보관위치 · 조치사항의 글자수 제한** | 그 필드의 상한과 검증 | 제품 — frame 에 hint 가 없다 |
| 2 | 저장 성공 뒤의 목적지(목록인가 조회인가) — 아래 로컬 미러는 등록된 조회 화면을 언급하므로 원문의 등록·수정 문맥 재확인 필요 | `onSaved` 가 어디로 가는가 | 제품·원문 재관찰 |
| 3 | 등록·수정의 서버 계약 | 요청 입력과 성공 후 무효화 | 서버 계약 |

> 2026-09-21 로컬 근거 대조: [교차 화면 미러](../../docs/reference/zero-sol/notion/99-cross-screen.md)의
> “확인 : 등록된 조회 화면으로 이동” 행은 스마트프린터와 해당 원문 S12를 명시한다. 발권 미러의 등록
> 요약만으로는 이 전이를 확인할 수 없어 미확인 2의 후속 확인 경로로 남긴다. 외부 원문은 재관찰하지
> 않았으므로 기존 `sources.observed`와 확정 상태는 변경하지 않았다. 컴포넌트 공유 여부는 제품 정책에서
> 제외하며, 동일한 필드 집합이라는 관찰을 토대로 작업 설계에서 정한다.
