# 스마트프린터 목록

## 관찰

**검색 전 frame 이 없다.** 목록 Case 하나뿐이다.

### 검색 조건

| 항목 | 관찰된 것 |
| --- | --- |
| 기간 | 기준 **등록일 · 최근업데이트일** |
| 검색어 | 대상 **기기명 · 시리얼번호 · 모델명 · 제조사 · 보관위치 · 조치사항**. 다중 키워드 허용 |
| 상태 | 다중 선택 — 정상 · 고장 · 수리중 |
| 용도 | 다중 선택 — 내부발권용 · 현장발권용 |
| 사용상태 | 다중 선택 — 사용 · 사용안함 |

다중 선택 셋은 **default 가 전체**다.

### 보기·정렬

- 보기 default **100**.
- 정렬 default **등록일** (원문은 `or 마지막으로 설정한 값` 을 함께 적는다 — [미확인](#미확인) 1).
- 정렬 목록: 등록일 · 업데이트일 · 기기명 · 시리얼번호 · 모델명 · 제조사 · **네트워크** · 보관위치 ·
  기기상태 · 조치사항 · 구매일 · 용도 · 사용상태.

### 표

checkbox + 기기명 · 시리얼번호 · 모델명 · 제조사 · **네트워크** · 보관위치 · 기기상태 · 조치사항 ·
구매일 · 용도 · 사용상태 · `등록일/최근업데이트일`(정렬 축, 두 일시를 **한 셀에 두 줄**로).

### toolbar 우측

`선택 ▾`(cascade — 용도 ▸ / 사용상태 ▸) + `변경` · `선택복사` · `등록`.

## 정책

- **추론 재검토**: 종전에는 절 제목 「스마트프린터 리스트를 조회할 수 있다」에서 **진입 즉시 조회**를
  도출했다. 제목만으로 진입 시점을 확정하지 않는 [판독 규칙](../policies/evidence.md#진입-정책은-명시된-동작으로-확인한다)에 따라 미확인 6으로 남긴다.
- 행을 활성화하면 **조회 화면**으로 이동한다.
- 일괄 **변경**은 3단계다 — 미선택이면 거절 alert `변경할 항목을 선택해주세요. / 확인`(Case01),
  1개 이상이면 **확인** alert `선택 항목을 변경하시겠습니까? / 확인, 취소`(Case02) → **완료** alert
  `변경되었습니다. / 확인`. 완료를 확인하면 alert 이 닫히고 **변경 상태로 화면이 갱신**된다.
  확인 alert 의 취소는 alert 만 닫고 현상태를 유지한다.
- **선택복사**에 원문이 적은 것은 미선택 거절 alert(Case01) 하나뿐이다. **확인**·**완료** alert 는
  [미확인](#미확인) 5 다.

> 2026-09-17 갱신: 이전 판은 변경과 복사를 묶어 "둘 다 3단계"로 적었다. 위 미러 원문을 다시 대조해
> **변경만** 3단계로 적혀 있고 복사에는 Case01 만 있음을 확인했다. 묶었던 문장을 가르고 복사의
> 확인·완료 여부를 미확인 5 로 옮겼다. 옛 원장(`docs/reference/zero-sol/06-ticketing.md` 6.7.1
> toolbar 행)의 요약 셀은 아직 "변경/복사 확인·완료"로 묶여 있다 — 이 fact 가 그 화면의 정본이다.

## 상태와 소유자

> 2026-09-21 근거 분류 정정: 저장소 미러의 「발권 > 부가기능 > 스마트프린터 / 검색 gate」 행에는
> 검색 버튼 후 조회와 초기화 후 검색 전 상태가 적혀 있다. 제목에서 도출한 기존 추론과의 관계를
> 재확인해야 한다. 이번에는 저장소 미러만 대조했으며 Figma·Notion 원문 관찰 시점은 갱신하지 않았다.

| 값 | 소유자 |
| --- | --- |
| 목록 결과·건수 | Query |
| 검색 조건·보기·정렬·page | route search |
| 행 선택·변경 intent | 이 화면 |

| # | 무엇이 미확인인가 | 답에 따라 무엇이 달라지나 | 누구에게 묻나 |
| --- | --- | --- | --- |
| 1 | 보기·정렬의 "마지막으로 설정한 값" 보관 여부와 범위 | 진입 시 기본값의 출처 | 제품 |
| 2 | **`네트워크` 값의 출처** — 조회·등록·수정 frame 과 원문 어디에도 없다 | 그 컬럼과 정렬 축을 그릴 수 있는가 | 제품 |
| 3 | `선택복사` 성공 뒤의 진입(복사본으로 가는가, 목록에 남는가) | 완료 alert 다음의 이동 | 제품 |
| 4 | 목록 조회·일괄변경·복사의 서버 계약 | 요청 입력과 성공 후 무효화 | 서버 계약 |
| 5 | **선택복사의 확인·완료 alert** — 원문은 Case01 만 적고, 옛 원장 요약 셀은 변경과 묶어 확인·완료가 있다고 적는다 | 복사를 누른 뒤 단계가 하나인가 셋인가 | 제품 |
| 6 | 진입 즉시 조회 여부와 초기화 후 검색 전 상태의 관계 — 제목 기반 추론과 미러의 검색 gate 서술을 원문에서 재확인해야 함 | 최초 조회 조건·초기화 전이 | 제품·원문 재관찰 |
