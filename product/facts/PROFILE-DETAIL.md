# 내정보 조회

로그인한 운영자가 **자기 계정**을 여는 화면이다. ID 를 URL 로 받지 않는다 — 대상은 세션이 정한다.

## 관찰

`운영자정보` 섹션(접이식)이 **2열**로 값을 읽기 전용으로 보여 준다.

```text
아이디        | 비밀번호  → `비밀번호 변경` 버튼
이름          |
휴대폰번호    | 이메일
소속          |
가입경로      | 계정 상태
```

- 값은 **마스킹되지 않는다.** 휴대폰번호·이메일이 그대로 그려지고 `개인정보 전체보기` 류의 재인증
  버튼이 frame 에 없다. (11.1 운영자 조회와 다른 점이다 — 그 화면의 마스킹을 여기로 옮기지 않는다.)
- `가입경로`·`계정 상태` 는 badge 가 아니라 다른 값과 같은 평문이다(관찰값 `WEB` · `활성`).
- 하단에 `수정`(가운데, primary)과 `탈퇴`(우측 텍스트 링크).
- frame 에 `업데이트 내역` 절이 없다.

### frame 의 chrome 이 11.1 운영자 것이다 (충돌)

frame `13.1. 내정보 조회` 가 실제로 렌더한 제목은 `운영자 조회`, breadcrumb 은 `설정 > 운영자 > 조회`,
우측 상단에 `이메일/SMS 발송` 링크가 있다. Notion 은 이 화면을 **`GNB > 내정보`** 에 놓는다.
같은 사실(이 화면이 어디에 사는가)을 두 출처가 다르게 말하므로
[판독 규칙](../../docs/reference/zero-sol/README.md#판독-규칙)대로 **Notion 을 따른다** — frame 의 제목·
breadcrumb·발송 링크는 11.1 운영자 조회 artboard 를 복제한 잔재로 읽고 채택하지 않는다.
채택한 제목은 frame 이름과 Notion 절 제목이 함께 말하는 `내정보 조회` 다.

## 정책 (Notion 원문)

### 수정
- `수정 버튼 → 클릭시, 수정 화면으로 이동`

### 비밀번호 변경
- `비밀번호 변경 버튼 → 클릭시, 비밀번호 변경 alert 제공`
- 그 alert 의 원문은 **[비밀번호 변경 팝업]** 페이지다.
  - 본문 `변경할 비밀번호를 입력해주세요.`
  - 입력 `비밀번호` · `비밀번호 확인`, 버튼 `확인` · `취소`
  - `비밀번호`: 필수입력, 직접입력 / 영문 대·소문자, 숫자, 특수문자 중 **3종류 이상 조합** /
    **8~20자** / 연속된 숫자·문자 3자 이상 불가(`abc`, `123`) / 같은 숫자·문자 3자 이상 불가(`aaa`, `111`)
  - `비밀번호 확인`: 필수입력, 직접입력 / 8~20자 / 비밀번호와 동일한 값. **동일하지 않은 값을 입력 후
    포커스 이동 시 입력 오류 안내 메시지 노출**
  - `확인 : 유효성 체크`
    | Case | 조건 | 메시지 |
    | --- | --- | --- |
    | 01 | 비밀번호 글자수 or 문자 조합 오류 | 영문 대/소문자, 숫자, 특수문자 중 3종류 이상 조합하여 입력해주세요. |
    | 02 | 직전의 비밀번호와 동일 | 현재 사용 중인 비밀번호를 재사용할 수 없습니다. 다른 비밀번호를 입력해주세요. |
    | 03 | 비밀번호 확인이 비밀번호와 불일치 | 비밀번호와 동일하게 입력해주세요. |
    | 04 | 오류 없음 | 비밀번호가 변경되고 `[비밀번호 변경 alert]` 제공 |
  - `[비밀번호 변경 alert]` — `비밀번호가 변경되었습니다.` / `확인` → `확인 : alert 닫히고, 현상태 유지`
  - `취소 : alert 닫히고, 현상태 유지`
- **Case02 는 서버만 판정한다.** 직전 비밀번호는 클라이언트에 없다.

### 탈퇴
- `탈퇴 버튼 → 클릭시, 회원 탈퇴 alert 제공`
  - `탈퇴 후 즉시 탈퇴가 진행되며 복원할 수 없습니다. / 탈퇴를 진행하시겠습니까? / 비밀번호 [    ] / 확인, 취소`
- `확인 : 비밀번호 유효성 체크`
  - `Case01. 비밀번호가 일치할 경우 탈퇴 처리가 완료되며, 탈퇴 완료 alert 제공`
    → `탈퇴가 완료되었습니다. / 확인` → `확인 : alert 닫히고, 로그인 화면으로 이동`
  - `Case02. 비밀번호가 일치하지 않을 경우 오류 메시지 제공` → `메시지 : 비밀버호를 확인해주세요.`
    (원문 표기 그대로. `비밀버호` 는 원문의 오타이며 화면에는 `비밀번호를 확인해주세요.` 로 쓴다 —
    [미확인](#미확인) 4)
- `취소 : alert 닫히고, 현상태 유지`
- 일치 여부는 **서버가 판정한다.**

## 상태와 소유자

| 값 | 소유자 |
| --- | --- |
| 내 계정 레코드 | Query (세션이 대상을 정하므로 ID param 이 없다) |
| 비밀번호 변경·탈퇴 다이얼로그의 입력과 수명 | 이 화면 |
| 탈퇴 완료 뒤의 이동 | route |

## 미확인

| # | 무엇이 미확인인가 | 답에 따라 무엇이 달라지나 | 누구에게 묻나 |
| --- | --- | --- | --- |
| 1 | `계정 상태`·`가입경로` 의 **값 집합**. frame 은 `활성`·`WEB` 한 값씩만 그린다 | enum 으로 선언하고 tone 을 줄 수 있는가. 지금은 서버가 준 표시 문자열을 그대로 그린다 | 제품·서버 계약 |
| 2 | 조회·비밀번호 변경·탈퇴의 **서버 계약** (내 계정 endpoint, 비밀번호 재사용·불일치의 오류 코드) | 응답 매핑과 Case02·불일치 메시지를 어떤 실패로 받는가 | 서버 계약 |
| 3 | 탈퇴 완료 뒤 **저장된 자격증명 처리**. 원문은 `로그인 화면으로 이동`만 말한다 | 이동만 하는가, 토큰까지 지우는가 | 제품 |
| 4 | 탈퇴 비밀번호 불일치 메시지의 정확한 표기(`비밀버호` 오타) | 화면 문구 | 제품 |
| 5 | frame 의 `이메일/SMS 발송` 링크가 내정보에도 있는 기능인지 | 헤더 액션이 있는가 | 제품 |
