# 내정보 수정

**등록이 없다.** 원장에 내정보 등록 화면이 없고, 대상은 세션이 정하므로 ID param 도 없다.

## 관찰

`운영자정보` 섹션 하나. 2열이고 화면 순서(좌→우, 위→아래)는 아래와 같다.

| 자리 | 항목 | 필수 | 관찰 |
| --- | --- | --- | --- |
| 1 | 아이디 | — | **입력이 아니라 읽기 전용 텍스트**(관찰값 `ididi1234`). Notion `아이디 → 수정 불가` |
| 2 | 비밀번호 | `*` | 라벨 옆에 **`수정` 체크박스**. 입력은 비활성 상태로 그려져 있고 placeholder 는 `영문 대/소문자+숫자+특수문자 중 3종류 이상, 8~20자 내외` |
| 3 | 비밀번호 확인 | `*` | 같이 비활성. placeholder `비밀번화 확인`(원문 오타 — [미확인](#미확인) 3) |
| 4 | 이름 | `*` | 관찰값 `김땡땡` |
| 5 | 휴대폰번호 | `*` | 관찰값 `010-1234-1234` |
| 6 | 이메일 | `*` | 관찰값 `your@email.com` |
| 7 | 소속 | — | `*` 가 없다. 관찰값 `부스터랩/제로플러스` |

하단 가운데에 `저장`(primary) · `취소`.

조회에 있는 `가입경로`·`계정 상태` 는 **이 frame 에 없다.** 조회의 `비밀번호 변경` 버튼도 없다 —
여기서는 체크박스로 같은 일을 한다.

### frame 의 chrome 이 11.1 운영자 것이다 (충돌)

제목 `운영자 수정`, breadcrumb `설정 > 운영자 > 조회 > 수정`. 해소는 [PROFILE-DETAIL](PROFILE-DETAIL.md)
과 같다 — Notion 의 `GNB > 내정보` 를 따르고 채택 제목은 `내정보 수정` 이다.

## 정책 (Notion 원문)

- `비밀번호 → 수정 체크박스 default : 비활성화`
- `비밀번호 → 수정 체크박스 활성화시, 입력필드 활성화`
- `비밀번호 → 필수입력, 직접입력`
- `비밀번호 → 입력 가능 문자 : 영문 대/소문자, 숫자, 특수문자 중 3종류 이상 조합`
- `비밀번호 → 입력 가능 글자수 : 8~20자`
- `비밀번호 → 연속된 숫자 또는 문자 3자 이상 입력 불가 (예 : abc, 123)`
- `비밀번호 → 같은 숫자 또는 문자 3자 이상 입력 불가 (예 : aaa, 111)`
- `비밀번호 확인 → 비밀번호와 동일한 값 입력` / `동일하지 않은 값을 입력 후 포커스 이동 시, 입력 오류 안내 메시지 노출`
- `저장 버튼 → 클릭시, 유효성 체크`
  - `Case02. 입력값이 모두 유효한 경우 저장 확인 alert 제공` → `저장하시겠습니까? / 확인, 취소`
- `취소 버튼 → 클릭시, 취소 alert 제공`
  → `취소할 경우 입력된 정보는 모두 삭제됩니다. / 입력을 취소하시겠습니까? / 확인, 취소`

`비밀번호` 의 `필수입력` 은 **체크박스를 켰을 때**를 말한다 — 끈 상태가 default 이고 그때 입력은
비활성이다.

## 상태와 소유자

| 값 | 소유자 |
| --- | --- |
| 조회 값(폼 초기값의 출처) | Query — 조회와 같은 key |
| 입력·dirty·필드 오류 | TanStack Form (`useSaveForm`) |
| 비밀번호 수정 여부 | 같은 폼의 boolean 필드 |
| 저장 확인·완료, 취소·이탈 질문 | `useSaveForm` |
| 저장·취소의 목적지 | route |

## 미확인

| # | 무엇이 미확인인가 | 답에 따라 무엇이 달라지나 | 누구에게 묻나 |
| --- | --- | --- | --- |
| 1 | `Case01`(입력값 오류)의 화면 고유 문구. 원문이 Case02 부터 적고 있다 | 필드 오류 문구를 화면 고유로 쓰는가 공용으로 쓰는가. 지금은 [화면 간 정책](../../docs/reference/zero-sol/README.md#현재-제품의-공통-정책)대로 오류 종류에 맞는 공용·원문 문구를 쓴다 | 제품 |
| 2 | 이름·휴대폰번호·이메일·소속의 **길이·문자 제한**. 원문이 비밀번호만 적는다 | 그 필드의 검증 규칙 | 제품 |
| 3 | `비밀번화 확인` placeholder 의 정확한 표기(원문 오타) | placeholder 문구 | 제품 |
| 4 | 저장의 **서버 계약**(내 계정 수정 endpoint, 비밀번호 동봉 방식) | 요청 payload 와 실패 분류 | 서버 계약 |
