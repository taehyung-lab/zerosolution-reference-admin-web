# 약관 조회

## 관찰

제목·브레드크럼은 `{약관1} 조회` · `설정 > {약관1} > 조회` 다(자리표시자는 [TERMS-LIST](TERMS-LIST.md) 미확인 6).

### 기본정보 (접이식 섹션)

| 행 | 관찰된 것 |
| --- | --- |
| 버전 | `V 1.0` — 목록의 `V1.2` 와 띄어쓰기가 다르다 |
| 시행일 | `2026-06-01 12:12:00` |
| 게시 상태 | 현재 값 `게시` 옆에 **반대 상태로 바꾸는 버튼** `게시안함` 하나. 같은 행 오른쪽에 `게시일` `2026-06-01 12:12:00` |
| 본문 | 테두리 상자 안의 서식 있는 긴 글. 굵은 문장과 문단이 섞여 있다 |

### 업데이트 이력 (접이식 섹션)

3열 표 — `업데이트일` · `업데이트 사항` · `담당자`. 예시 행은 `2026-06-01 12:12:11` · `등록` ·
`김땡땡 (adminuser)` 하나다. Notion 은 `업데이트 내역 → 업데이트일 : 수정되어 저장된 날짜` 라 적어
수정도 이 표에 쌓인다고 말한다.

### 하단

`수정`(primary) · `삭제`.

## 정책

- `수정 버튼 → 클릭시, 수정 화면으로 이동`.
- `삭제 버튼 → 클릭시 삭제 확인 alert 제공 → 삭제하시겠습니까? / 확인, 취소`.
- 게시 상태 전환은 확인 alert 을 지난다 — `게시안함 버튼 → 클릭시, 상태 변경 alert 제공 →
  게시안함으로 변경하시겠습니까? / 확인, 취소 → 확인 : alert 닫히고, 게시안함으로 변경되며 화면 갱신됨`.
  반대 방향(`게시` 로 되돌리기)의 문구는 원문에 없다([미확인](#미확인) 1).

## 상태와 소유자

| 값 | 소유자 |
| --- | --- |
| 약관 한 건 | Query (`termsId` 기반) |
| 상태 전환·삭제의 확인 lifecycle | 이 화면 |

## 미확인

| # | 무엇이 미확인인가 | 답에 따라 무엇이 달라지나 | 누구에게 묻나 |
| --- | --- | --- | --- |
| 1 | **`게시` 로 되돌리는 확인 문구.** 원문은 `게시안함으로 변경하시겠습니까?` 한 방향만 적는다 | 반대 방향 alert 의 문장 | 제품 |
| 2 | **`업데이트 사항` 의 종류 집합과 항목별 변경 줄.** frame 은 `등록` 하나만 그리고 형제 화면(9.2.2 게시물)처럼 `항목 : 이전 > 이후` 줄을 쓰는지 말하지 않는다 | 이력 한 줄의 구성 | 제품 |
| 3 | 삭제 성공 뒤의 이동 목적지 | 삭제 후 화면 | 제품 |
| 4 | 조회·상태 전환·삭제의 서버 계약 | 요청 입력과 성공 후 무효화 | 서버 계약 |

## 보류

- 이력의 항목별 변경 줄은 미확인 2 때문에 만들지 않는다. 종류 낱말(`등록`·`수정`) 한 줄만 그린다.
