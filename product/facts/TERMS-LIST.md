# 약관 목록

## 관찰

**검색 전 frame 이 없다.** `11.2. 약관` 페이지의 top-level frame 은 리스트 · Case 정의 · 조회 ·
등록 · 수정 다섯이고 검색 안내 화면은 없다.

화면 제목과 브레드크럼은 `{약관1}` · `설정 > 약관 > {약관1}` 이다 — LNB 도 `약관` 아래에 `{약관1}`
항목을 그린다([미확인](#미확인) 6). 제목 옆 도움말 말풍선은 `약관을 조회 및 관리합니다.`

### 검색 조건

| 항목 | 관찰된 것 |
| --- | --- |
| 기간 | 기준 **등록일 · 최근업데이트일 · 시행일 · 게시일**(닫힌 상태는 `등록일`). preset 전체(기본) · 1년 전 · 6개월 전 · 3개월 전 · 1개월 전 · 7일 전 · 어제 · 오늘 + 직접 범위 |
| 검색어 | 대상 **본문 · 내용**(닫힌 상태는 `본문`). `⊕ 추가` 로 다중 키워드, chip 은 `본문 : 보안` 형태 |
| 게시 상태 | 다중 선택 — 전체 \| 게시 · 게시안함. Notion `default : 전체` |

### 보기·정렬

- 보기 default **100**, 목록 100 · 200 · 300 · 400 · 500 · 700 · 1000.
- 정렬 default **등록일**(원문은 `or 마지막으로 설정한 값` 을 함께 적는다 — [미확인](#미확인) 7).
- 정렬 목록: 등록일 · 최근업데이트일 · 시행일 · 게시일 · 버전 · 본문 · 게시 상태.

### 표

checkbox + 버전 · 본문 · 시행일 · 게시 상태 · 게시일 · `등록일/최근업데이트일`(정렬 축, 두 일시를
**한 셀에 두 줄**로).

표시 형식: 버전은 `V1.2`, 본문은 **한 줄로 줄이고 `…`** 로 자른다, 일시는 `2026-06-01 12:00:00` 로
초까지. 예시 행에 빈 값 표기는 없다.

### toolbar 우측

`선택 ▾`(cascade — 게시 상태 ▸ 게시 · 게시안함) + `변경` · `선택복사` · `등록`.

### paging

표 아래 `← Previous 1 2 3 … 67 68 Next →`. 표 끝에는 `- 이하 생략 -` 자리표시자가 있다.

## 정책

- 행을 활성화하면 **조회 화면**으로 이동한다(원문 `특정 행 클릭시, 조회 화면으로 이동`).
- `등록` 은 **등록 화면**으로 이동한다(원문 `등록 버튼 → 클릭시, 등록 화면으로 이동`).
- 검색은 `검색 조건에 부합하는 검색결과 호출`, 초기화는 `검색 조건을 default 로 설정값을 변경` 이다.
  같은 문장이 이어서 `및 검색 전 상태로 변경` 이라고 적는데 frame 에는 검색 전 상태가 없다
  ([미확인](#미확인) 3).
- 일괄 **변경**은 3단계다 — 미선택이면 거절 alert `변경할 항목을 선택해주세요. / 확인`(Case01),
  1개 이상이면 **확인** alert `선택 항목을 변경하시겠습니까? / 확인, 취소`(Case02) → **완료** alert
  `변경되었습니다. / 확인` → `확인 : alert 닫히고, 변경 상태로 화면 갱신됨`. 확인 alert 의 취소는
  alert 만 닫고 현상태를 유지한다.
- **선택복사**에 전사가 적은 것은 미선택 거절 alert(Case01) 하나뿐이다. 옛 원장
  `docs/reference/zero-sol/11-settings.md` 의 Notion 요점은 스마트프린터·약관·접근권한을 묶어
  `1개 이상 선택시, 복사 완료 alert` 이라고 적지만 전사의 약관 절에는 그 문장이 없다
  ([미확인](#미확인) 4). 같은 충돌을 `PRINTER-LIST` 미확인 5 도 소유한다.

## 미확인

| # | 무엇이 미확인인가 | 답에 따라 무엇이 달라지나 | 누구에게 묻나 |
| --- | --- | --- | --- |
| 1 | **`게시 상태` 행을 리스트 frame 이 그리지 않는다.** 리스트 frame 은 검색어 행과 `검색`·`초기화` 사이에 빈 공간만 두고, 같은 자리를 Case 정의 frame 과 Notion(`검색 영역 → 게시 상태 → default : 전체`)은 필터로 적는다 | 검색 영역에 그 행이 있는가 | 디자인 원문 소유자 |
| 2 | **검색어 대상 `내용` 이 가리키는 값.** 등록·수정 frame 에는 `본문 *` 입력 하나뿐이고 조회 frame 도 `본문` 한 줄만 그린다 | 두 대상이 서로 다른 값을 찾는가, 같은 값의 다른 이름인가 | 제품·서버 계약 |
| 3 | **진입 즉시 조회 여부.** frame 에 검색 전 상태가 없고, 검색 gate 를 가진 11.1 운영자에게만 있는 「화면 진입시, 검색 안내 화면이 제공된다」 절이 약관 원문에는 없다. 반면 초기화 문장은 `검색 전 상태로 변경` 이라고 적는다 | 최초 조회 조건과 초기화 전이 | 제품 |
| 4 | **선택복사의 확인·완료 alert.** 전사는 Case01 만 적고 옛 원장 요약 셀은 복사 완료 alert 이 있다고 적는다 | 복사를 누른 뒤 단계가 하나인가 둘인가, 완료 문구는 무엇인가 | 제품 |
| 5 | **버전 표기가 자리마다 다르다.** 목록은 `V1.2`, 조회·폼은 `V 1.0` 으로 띄어 그린다 | 두 표기를 하나로 맞추는가 | 디자인 원문 소유자 |
| 6 | **LNB·제목의 `{약관1}`.** `약관` 아래 항목 하나를 고른 상태로 보이지만 그 항목 목록의 출처·개수·URL 을 원문이 말하지 않는다 | 이 목록이 약관 종류마다 따로 열리는가(그러면 URL 에 종류 식별자가 붙는다), 제목이 무엇인가 | 제품 |
| 7 | 보기·정렬의 "마지막으로 설정한 값" 보관 여부와 범위 | 진입 시 기본값의 출처 | 제품 |
| 8 | 목록 조회·일괄변경·복사의 서버 계약 | 요청 입력과 성공 후 무효화 | 서버 계약 |

## 보류

- 약관 종류별 진입은 미확인 6 때문에 보류한다 — 목록은 종류 식별자 없는 한 URL 로 열고 제목은 LNB 가 확인한 메뉴 이름 `약관` 을 쓴다.
- 검색어 대상 두 개는 미확인 2 때문에 둘 다 남기되 어느 값을 찾는지는 서버가 가른다.
- 선택복사 뒤의 완료 alert 은 미확인 4 때문에 만들지 않는다.
