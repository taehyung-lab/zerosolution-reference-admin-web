# 전체발권 목록

발권 업무군의 첫 목록. 「전체 발권 내역을 조회할 수 있다」(Notion 4) 사용자 시나리오).

## 구성

진입은 **검색 전**이다. Notion 이 「화면 진입시, 검색 안내 화면이 제공된다」로 명시하고 검색전 frame 이
검색 패널 + `검색해주세요.` 한 문장만 그린다. 검색 실행 뒤에 결과 영역이 나타난다.

검색 패널은 **공연 선택 여부로 두 모양**을 갖는다. Notion 「검색 영역 → 공연 검색 → 공연 선택 후 추가
검색 조건이 제공된다」·「공연일 → 공연 검색에서 공연 선택 후 제공」, 그리고 검색전 frame 에 공연일이
없고 검색후 frame 에 있다는 관찰이 같은 말을 한다.

| 자리 | 공연 미선택 | 공연 선택 후 |
| --- | --- | --- |
| 공연 검색 | 있음 (입력 + 🔍) | 선택 결과 chip `[서울] IVE THE FIRST FAN CONCERT` + ⓧ |
| 공연일 `*` | 없음 | 있음 |
| 기간 | 있음 | 있음 |
| 검색어 | 있음 | 있음 |
| 결제금액 · 예매처 · 예매상태 · 발권상태 · 재발권상태 | 없음 | 있음 ([미확인](#미확인) 1) |

검색 패널 밖의 구성: 결과 상태 카운트 → 보기·정렬 → toolbar(일괄변경·다운로드) → 표 → 페이지.
등록 버튼은 세 frame 어디에도 없다.

### 검색 조건

| 행 | 관찰된 값 | 기본값 |
| --- | --- | --- |
| 공연 검색 | 입력 하나. 고르면 `[장소] 공연명` chip 하나 + ⓧ. `*` 없음 | 없음 |
| 공연일 `*` | `선택` / `전체` / `1회차 2026-01-03 14:00 ~ 2026-01-03 16:00` / `2회차 2026-01-04 14:00 ~ 2026-01-04 16:00` — 선택한 공연의 회차 | `전체`(Notion 「공연일 → default : 전체」) |
| 기간 | 기준 7개: 예매일 · 예매취소일 · 발권일 · 발권취소일 · 분실일 · 등록일 · 최근업데이트일. preset `전체 / 1년 전 / 6개월 전 / 3개월 전 / 1개월 전 / 7일 전 / 어제 / 오늘` + 날짜 범위 | 기준 `예매일`, preset `전체` |
| 검색어 | 대상 7개: 예매번호 · 좌석번호 · 등급 · 예매자 이름 · 예매자 휴대폰번호 · 결제수단 · 할인정보. 다중 키워드(chip `예매번호 : 000001`) | 대상 `예매번호` |
| 결제금액 | 양끝 handle slider, 라벨 `0~200,000` | [미확인](#미확인) 2 |
| 예매처 | `전체` │ 제로플러스 · 멜론티켓 · 티켓링크 · 놀유니버스 · 예스24 · 기타. 다중선택 | `전체` |
| 예매상태 | `전체` │ 예매완료 · 예매취소. 다중선택 | `전체` |
| 발권상태 | `전체` │ 발권완료 · 분실. 다중선택 | `전체` |
| 재발권상태 | `전체` │ 신규발권 · 재발권 **(** CS 분실 · CS 인쇄불량 · CS 기타 · 일반 **)**. 다중선택 | `전체` |

`전체`는 조건 없음이다(Notion 「default : 전체」). 재발권의 괄호 넷은 `재발권` 아래 한 단 들여쓴
하위 항목으로 그려져 있다.

검색 패널의 제목·검색·초기화·기간·검색어·추가·전체는 [LIST-COMMON-COPY](LIST-COMMON-COPY.md) 가 소유하는 공통 문구다.
`초기화`는 「검색 조건을 default로 설정값을 변경 및 검색 전 상태로 변경」이다 — 기본값 복원이자 검색
전으로의 복귀다.

### 결과 상태 카운트

frame 은 결과 영역 맨 위 가운데에 다섯 항목을 link 모양(밑줄)으로 나열한다.

```
총 1,100   발권대기 500   발권완료 500   재발권 100   분실 100
```

Notion 은 「각 상태별 검색결과 수 표기 → 클릭시, 해당 상태만 필터링하여 검색결과 조회 가능」이라고
적는다. 무엇을 어느 필드로 커밋하는지는 [미확인](#미확인) 3.

### 보기·정렬

- 보기: `100`. Notion 「default : 100 or 마지막으로 설정한 값」 — 마지막 값 보관은 [미확인](#미확인) 4.
- 정렬 19축, frame 목록 순서대로: 등록일 · 최근업데이트일 · 예매일 · 예매취소일 · 발권일 · 공연유형 ·
  공연명 · 회차 · 공연일 · 예매번호 · 좌석번호 · 등급 · 예매자 이름 · 예매자 휴대폰번호 · 결제수단 ·
  결제금액 · 할인정보 · 예매처 · 발권상태. 기본값 `등록일`(닫힌 select 가 `등록일`, Notion 「default :
  등록일 or 마지막으로 설정한 값」).

기간 기준에는 있고 정렬축에는 없는 것이 둘이다: **발권취소일 · 분실일**. 반대로 정렬에만 있는 것이
**발권상태**다. 원장 `docs/reference/zero-sol/06-ticketing.md` 6.2 행은 이 화면의 날짜 정렬을
`예매일·예매취소일·발권일·발권취소일` 로 적었으나 frame 은 발권취소일을 포함하지 않는다 —
frame 판독이 정본이다.

### toolbar

| 자리 | 관찰 |
| --- | --- |
| 일괄변경 | select `선택` → cascade `발권상태 >` → `발권취소` · `분실`. 옆에 `변경` link |
| 다운로드 | select `선택한 항목` · `검색결과 전체` (기본 미선택) + `다운로드` link |

### 표

checkbox 열 + 7열이다. 앞 넷은 한 셀에 `항목 : 값` 을 여러 줄로 쌓는 복합 셀이다.

| 열 | 셀 내용(검색후 frame 원문) |
| --- | --- |
| 공연정보 | `공연유형 : 콘서트` / `공연명 : [서울] IVE THE FIRST FAN CONCERT` / `회차 : 1회차` / `공연일 : 2026-01-03 14:00` |
| 예매정보 | `예매번호 : ZERO123456789` / `좌석번호 : 1층 1구역 1열 001` / `등급 : VIP` / `티켓일련번호 : 12****23` |
| 예매자정보 | `이름 : 김제로` / `휴대폰번호 : 010-****-1234` |
| 결제정보 | `결제수단 : 신용(한국)카드` / `결제금액 : 150,000원` / `할인정보 : -` / `예매처 : 제로플러스` |
| 발권상태 | `발권취소` · `발권대기` · `발권완료` · `분실` 중 하나 |
| 최근발권일 | `2026-06-01 12:00:00`, 발권 전 행은 `-` |
| 등록일/최근업데이트일 | 두 일시를 한 셀에 두 줄. 정렬 아이콘이 이 열에 있다 |

표 아래에 `- 이하 생략 -` 안내줄, 그 아래 `← Previous 1 2 3 … 67 68 Next →`.

## 표시 형식

| 값 | 관찰된 표기 |
| --- | --- |
| 예매자 휴대폰번호 | `010-****-1234` — 가운데 4자리 마스킹([CONTACT-MASKING](CONTACT-MASKING.md) 과 같은 모양) |
| 티켓일련번호 | `12****23` — 앞 2·뒤 2만 남긴다 |
| 결제금액 | `150,000원` — 천 단위 구분 + `원` |
| 빈 값 | `-` (할인정보·최근발권일) |
| 공연일 | `2026-01-03 14:00` — 분까지 |
| 등록일·최근업데이트일·최근발권일 | `2026-06-01 12:00:00` — 초까지 |
| 회차 | `1회차` |

## 연결

- 위치: 발권 > 전체발권. LNB 발권 하위는 frame 기준 `등록(일반발권 · 대량재발권)` · `전체발권` ·
  `발권대기` · `발권완료(신규발권 · 재발권)` · `분실` · `부가기능(스마트프린터)` 순이다.
- 화면 제목 `전체발권`, breadcrumb `발권 > 전체발권`, 제목 옆 ⓘ tooltip 「전체 발권 내역을 조회할 수 있습니다.」
- 데이터 범위 권한: 「DTsol에서 본인이 담당자로 지정된 공연 리스트만 조회할 수 있다」 — 서버가 조회
  범위를 좁힌다는 진술이며 화면의 분기가 아니다.
- 행 클릭 목적지는 발권 조회(6.6)다. 그 화면의 구성·정책은 그 화면의 fact 가 소유한다.

## 미확인

| # | 무엇이 미확인인가 | 답에 따라 달라지는 것 | 누구에게 |
| --- | --- | --- | --- |
| 1 | 결제금액·예매처·예매상태·발권상태·재발권상태가 **검색후 frame 에 그려져 있지 않다.** Case 정의 frame 과 Notion 은 다섯을 모두 말한다 | 다섯 조건이 공연 선택 뒤에 함께 나타나는지, 아니면 검색후 frame 이 최신인지 | 디자인 원문 소유자 |
| 2 | 결제금액 slider 의 **최소·최대·단위의 출처**. `0~200,000` 이 제품 상수인지 데이터에서 온 값인지, 어떤 요청 필드로 나가는지 원문이 말하지 않는다 | 이 조건을 그릴 수 있는지, 값을 어디서 읽는지 | 제품·서버 |
| 3 | 상태 카운트 클릭이 **어떤 필드에 무엇을 커밋하는지**. 발권상태 필터 선택지는 발권완료·분실 둘뿐이라 `발권대기`·`재발권` 을 옮길 자리가 없다 | 다섯 항목이 버튼인지 표시인지, 각각의 커밋 값 | 제품 |
| 4 | 보기·정렬의 「or 마지막으로 설정한 값」 보관 범위(세션·계정·기기) | 기본값을 URL 밖에 저장하는지 | 제품 |
| 5 | 공연 검색이 **팝업인지**. Notion 은 「공연검색 팝업 활성화」라고 적고 세 frame 은 입력 + chip 만 그린다. 팝업 결과 표의 열 구성은 6.2 frame 에 없다 | 공연 고르기의 표면과 그 표의 열 | 디자인 원문 소유자 |
| 6 | 공연일의 `*` 가 **검색을 막는지**. 기본값이 `전체` 라 미충족 상태가 생기지 않고, 차단 문구도 원문에 없다 | 필수 미충족 시의 차단·문구 | 제품 |
| 7 | 발권상태 **필터 선택지(발권완료·분실)와 표 값(발권취소·발권대기·발권완료·분실)의 불일치** | 발권취소·발권대기를 조건으로 고를 수 있는지 | 제품 |
| 8 | 다운로드의 **파일 형식·열 구성**, 그리고 범위를 고르지 않고 `다운로드` 를 눌렀을 때 | 다운로드 요청 입력과 미선택 처리 | 제품 |
| 9 | 다운로드 Case02(선택 없음 + `선택한 항목`) **오류 alert 의 문장**. 미러는 「오류 alert 가 제공됨」까지만 적고 문구를 인용하지 않는다 | 그 alert 의 문구 | 제품 |

## 보류

- 미확인 2 — 결제금액 조건은 그리지 않는다. 최대값·단위·요청 필드를 지어내면 다음 사람이 확정으로 읽는다.
- 미확인 3 — 상태 카운트는 표시로만 그린다. 커밋 대상이 정해지면 버튼으로 바꾼다.
- 미확인 7 — 발권상태 조건은 frame 이 열거한 발권완료·분실 둘만 그린다.
- 미확인 8 — 범위를 고르지 않은 `다운로드` 는 아무 요청도 만들지 않는다. 확인·완료 alert 도 만들지 않는다.
- 미확인 9 — 문구를 지어내지 않고 저장소가 이미 소유한 미선택 거절 문장을 그대로 쓴다.
