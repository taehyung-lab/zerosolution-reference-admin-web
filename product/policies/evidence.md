# 정책 — 근거의 종류와 수명

모든 fact 가 따르는 판독 규칙이다. fact 는 관찰을 적고, 이 문서는 **그 관찰을 어떻게 읽고 언제
다시 봐야 하는지**를 정한다.

## 근거의 종류를 구별한다

| 표기 | 뜻 |
| --- | --- |
| **확인** | 제품 원문(디자인 frame · 기능 문서)을 실제로 열어 관찰했다. 언제·어떻게 관찰했는지를 fact frontmatter 의 `sources` 가 적는다 |
| **추론** | 확인된 관찰에서 나온 설계 판단. 제품이 그렇게 말한 것은 아니다 |
| **가정** | 진행하려고 임시로 정한 것. 틀리면 무엇이 달라지는지 함께 적는다 |
| **미확인** | 답이 없다. fact 의 `미확인` 표가 소유하고, 답에 따라 무엇이 달라지는지와 누구에게 묻는지를 적는다 |

넷을 섞지 않는다. 특히 **추론을 확인으로 승격하지 않는다.**

## 코드는 제품 사실의 근거가 아니다

새로 쓴 코드·기존 코드·테스트 통과·구현 설명은 제품이 그렇게 정했다는 증거가 아니다. 그것으로
fact 의 관찰·정책·미확인을 바꾸지 않는다.

fixture 와 예시 값도 마찬가지다. 예시 파일이 `.txt` 라는 사실은 허용 확장자의 증거가 아니고,
예시 행의 개수는 제품의 상한이 아니다.

**형제 화면은 더더욱 근거가 아니다.** 코드는 늘 가장 가까운 다른 화면을 답으로 준다.

## "없다"를 쓸 수 있을 때

`X 가 없다`는 **X 의 실제 소유자를 직접 확인했을 때만** 쓴다. 색인에 없거나, 코드에 없거나,
검색에 안 걸린 것은 `미확인`이지 부재가 아니다.

fact 에 적힌 부재(예: "등록 화면이 원장에 없다")는 그 원장을 실제로 읽은 결과이며, 그 이상을
뜻하지 않는다 — "제품에 그 기능이 없다"로 넓히지 않는다.

**도구는 원문을 잘라 내거나 거부를 성공 종료로 되돌릴 수 있다.** 빈 출력·잘린 출력은 부재가 아니라
미확인이다. 무엇을 어떤 도구로 열었고 어디서 끊겼는지를 적는다.

## 절 제목이 진입 정책을 말한다

기능 원문의 절 제목이 **「… 리스트를 조회할 수 있다」** 형태면 그 목록은 **진입 즉시 조회**다.
검색을 먼저 요구하는 화면은 원문이 "화면 진입 시 검색 안내 화면이 제공된다"처럼 그 사실을 따로 적는다.

frame 이 검색 전 상태를 그리지 않았다는 것만으로 진입 즉시 조회라고 판정하지 않는다 — 두 근거가
어긋나면 fact 에 둘 다 적고 미확인으로 남긴다.

## 화면 근거를 읽는 순서

**바뀌는 것만 연다.** 제품 값(문구·옵션·권한·기본값·컬럼 집합)이 바뀌면 아래 1~4가 근거다.
구조·상태·접근성만 바뀌고 제품 값은 그대로면 원장·디자인을 열지 않고 5와 계약 skill의 해당 절로
닫는다. 어느 쪽인지 모르면 1만 먼저 보고 정한다.

1. `product/generated-index.md`에서 해당 fact를 찾고 그 fact가 선언한 source·policy만 연다.
2. 구성의 미열거·충돌·시각 대조가 있으면 fact의 source owner가 정한 절차로 실제 원문을 판독한다.
3. 부모·목적지 route와 실제 소비자를 확인한다. 필요한 연결 범위는 [`AGENTS.md`](../../AGENTS.md)가 정한다.
제품 값은 원장·그 값의 원문, 파일·URL 조립은 계약 skill, 실행 사실은 소비자·테스트가 소유한다.
다른 도메인이나 형제 화면의 값은 제품 근거가 아니다. 연결 목적지는 자기 원문을 읽는다.
색인·원장·시나리오의 존재나 부재를 완료 또는 구현 금지로 판정하지 않는다.

### 관찰표

| 축 | 무엇을 적나 |
| --- | --- |
| **구성** | 이 화면에 실제로 있는 surface 목록. 없는 책임을 빈 파일로 만들지 않는다 |
| **표시 형식** | 값이 **어떻게 보이는가** — 마스킹·빈 값 표기·날짜와 시각의 정밀도·단위·자릿수·나열 순서. 원장이 말하지 않으면 원문을 연다 |
| **상태** | 서버 데이터 / URL / 폼 / 로컬 각각의 소유자. 같은 값이 두 곳에 있으면 설계 결함 |
| **상호작용** | 각 액션의 진입 조건, 성공, 실패, 되돌리기 |
| **연결** | navigation, 권한 분기, i18n 키, 부모·형제 surface와의 경계 |

미확인 행은 원문 접근 실패·제품 부재·기술 의존으로 구별한다. 접근 경로를 먼저 수행하고, 제품이 답하지 않는 부분만 해소 조건을 남겨 보류한다.

## 원문 접근

fact의 `sources`가 가리키는 원문을 실제로 열고 접근 방법·범위·시점을 기록한다. 접근 수단은 저장소의
source owner가 정하며 이 범용 정책은 특정 브라우저·계정·도구를 요구하지 않는다. 원문을 읽지 못했으면
`observed`를 갱신하지 않고 접근 실패와 영향을 보고한다.

## 관찰의 수명

- fact 의 `sources.observed` 가 그 관찰의 시점이다. 원문이 바뀔 수 있는 종류(디자인 frame ·
  기능 문서)는 **그 값을 다시 쓰는 작업에서 다시 관찰**하고 시점을 갱신한다.
- 관찰을 갱신하면 **무엇이 달라졌는지**를 fact 안에 남긴다. 조용히 덮어쓰지 않는다.
- `현재 코드` 절은 구현이 바뀌면 낡는다. 그 절을 근거로 제품 값을 정하지 않는다.
- fact 의 `status` 는 `관찰됨`(원문을 봤다) · `확정됨`(제품 소유자가 답했다) · `미확인`(아직
  못 봤다) 중 하나다. 구현이 끝났다는 이유로 올리지 않는다.

## 화면에 문장을 더하려면 원문이 그 문장을 말해야 한다

검사·차단·확인·완료를 더하는 것은 — 그리고 **그것을 알리는 문장**을 더하는 것은 — 제품 동작을 더하는
것이다. 그 **발동 조건**과 **제품이 그것을 말하는 형태**를 둘 다 fact 의 관찰이나 사용자의 명시적
결정과 대조한다.

fact 가 `필드 강조`·`선택 불가` 라고만 말하면 그 오류 종류의 제품 기본 문구를 쓴다. fact 가 답하지
않는 동작은 만들지 않고 묻는다. 번역 키 짝이 맞는다는 사실(`i18n:check`)은 제품이 그 문장을 말한다는
증거가 아니다 — 그것은 세 locale 의 키 집합이 같다는 뜻일 뿐이다.

## 미확인을 다루는 법

미확인은 **작업을 멈추는 사유가 아니다.** 답에 따라 제품 동작·권한·API·범위가 달라지는 부분만
보류하고, 확인된 나머지는 진행한다. 보류한 부분에는 무엇을 물어야 하는지와 어떤 조건이 충족되면
풀리는지를 적는다.

목적지 화면이 없다는 사실은 범위 질문의 사유가 아니다. 확정된 전이에 필요한 실제 목적지는 같은
작업에서 만든다. 다만 **그 목적지의 구성·정책은 그 목적지의 fact 로 확인하며** 요청 화면이나 다른
도메인에서 복사하지 않는다. 빈 route·stub 은 목적지가 아니다.

값을 지어내는 것보다 미확인으로 남기는 것이 항상 낫다. 지어낸 값은 다음 사람에게 확정으로 읽힌다.
